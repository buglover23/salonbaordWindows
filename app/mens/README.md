# SALON BOARD 自動投稿ツール（Plan 4：起動.bat と運用）

美容室の写真から SALON BOARD のスタイル・ブログ投稿を準備し、決まった時間帯に1件ずつ投稿するための、Windows のパソコンで動かすツールです。

写真を AI（初期設定は Google の Gemini の無料枠。設定を変えれば Anthropic 社の Claude も使えます）で解析して投稿の文章を作り、検査に通ったものを、**オーナーが Chrome でログインしている SALON BOARD に、専用の Chrome 拡張機能を通して1件ずつ登録します**（Plan 3）。登録の後は、画面の完了表示と投稿一覧で本当に登録されたかを確かめます。

**本番投稿（SALON BOARD への実際の登録）は、下の「本番投稿の準備」がすべて終わるまで始まりません。** ツールが勝手に本番へ切り替わることはありません。準備が終わるまでは、画像の取込から「投稿したことにする」テスト運転（dry-run）までを、パソコンの中だけで確かめられます。**dry-run の初期設定では本物の AI を使わず、費用のかからない模擬の AI（mock）で動きます。**

## この版でできること・まだできないこと

| できること（Plan 1〜4） | まだできないこと（後の版で追加） |
|---|---|
| 設定ファイル（`config` フォルダ）の検査 | 失敗したときの画面の保存（スクリーンショット） |
| 4つの専用フォルダに置いた画像の取込（同じ画像の二重登録を防ぐ、読めない画像は理由付きで失敗にする）。写真ごとの補足ファイル（`.json`）も一緒に取り込みます | |
| AI による写真の解析と文章の作成、文章の検査と作り直し（下の「AI の設定」） | |
| Excel のテンプレート・公開トレンドの CSV・作業指示書を文章づくりの参考にする | |
| 1日の投稿枠づくり（初期値は 10:00〜21:00 にスタイル10件・ブログ10件、21:00 より前に終える） | |
| dry-run での擬似投稿（SALON BOARD には何も送りません）と、投稿履歴（重複を防ぐための記録） | |
| Chrome 拡張機能による SALON BOARD への登録と、登録できたかの確認（1回の送信につき1回だけ押す。結果が分からないときは自動では登録し直さず、照合します） | |
| 状態表示（`status`・拡張機能のポップアップ）、AI の利用量と予算の表示、途中で止まった処理の復旧、失敗した投稿の再開（`retry`）、一時停止と再開（`pause`・`resume`）、結果不明の照合（`reconcile`）、二重起動の防止 | |
| `起動.bat` のダブルクリックでの起動（予期しない終了のときの自動の起動し直し、Chrome を開く、タスク スケジューラの登録例）（Plan 4） | |
| 投稿済みのデータの30日後の自動整理、メモリ・ディスクの監視、ログとバックアップの整理（Plan 4） | |

> **「本番投稿の準備」が終わるまで、`config/settings.json` の `"mode"` は `"dry_run"` のままにしてください。**
> 準備の途中で `"live"`（本番）にしても、準備が終わっていない投稿先には投稿しません（`status` に「本番の準備で未完了の項目」が出ます）。ただし本番では、画像は pending から本番用のフォルダへ**移動**され、本物の AI で文章を作ります（費用がかかる場合があります）。

## 必要なもの

- Windows 11
- Node.js 24 LTS（このツールで確認した実際のバージョン: **v24.19.0**）。npm は Node.js に付いてきます。
- インターネット接続（最初の `npm.cmd ci` のとき。本物の AI を使うときは、その間も）
- 本物の AI を使う場合だけ：Google AI Studio で作る無料の API キー（下の「AI の設定」。Claude を使うときは Anthropic の API キー）。dry-run を模擬の AI で試すだけなら不要です。

### PowerShell では `npm` ではなく `npm.cmd` と入力してください

Windows の PowerShell では、セキュリティ設定（実行ポリシー）により `npm` と打つとエラーになることがあります。**設定を変える必要はありません。** 代わりに `npm.cmd` と入力すれば動きます。この README のコマンドはすべて `npm.cmd` で書いています。
（コマンドプロンプト `cmd.exe` を使う場合は、`npm` のままでも動きます。）

## 初回の手順

この手順は、プログラムの元（`src` フォルダ・`tsconfig.json` など）を含むフォルダ一式を受け取った前提です。手順3でプログラムを組み立てます。

1. このフォルダ（`package.json` があるフォルダ）で PowerShell を開きます。
   エクスプローラーでこのフォルダを開き、上のアドレス欄に `powershell` と入力して Enter を押すと、このフォルダで開きます。

2. 必要な部品を入れます（数分かかります）。

   ```powershell
   npm.cmd ci
   ```

3. プログラムを組み立てます。

   ```powershell
   npm.cmd run build
   ```

4. 設定ファイルを検査します。「問題はありません」と出れば大丈夫です。

   ```powershell
   npm.cmd run config:validate
   ```

5. 画像を置くフォルダを作り、画像を入れます。フォルダは次の1行で作れます（最初に `npm.cmd start` か dry-run を実行したときにも自動で作られます）。

   ```powershell
   New-Item -ItemType Directory -Force images\pending\style\mens, images\pending\style\ladies, images\pending\blog\mens, images\pending\blog\ladies
   ```

   スタイル投稿の男性の写真は `images\pending\style\mens`、女性は `images\pending\style\ladies`、ブログは `images\pending\blog\...` へ入れます（くわしくは「フォルダの説明」）。写真ごとに補足を書きたいときは、同じ名前の `.json` を隣に置きます（「写真ごとの補足ファイル」）。

   **スタイル投稿を試すときは、先に `config\salon.json` の `verified_menus` にお店のメニュー名を登録してください**（例：`"verified_menus": ["カット", "カット＋カラー"]`）。登録が無い間、スタイルの写真は準備せずに待たせます（費用もかかりません）。登録すると自動で準備を始めます。ブログは登録が無くても準備します。

   文章の参考にする Excel（テンプレート）の場所も `config\template_mapping.json` の `file_path` に書いておきます（「テンプレート（Excel）の取込」）。Excel が読めず、前に読み込んだ内容も無いときは、文章の作成を保留します。

6. dry-run を1回だけ実行します。次の例は「2026年10月5日 10:00（日本時間）だったら」というテストです。取り込んだ画像を模擬の AI で解析して文章を作り、検査に通ったものを「投稿待ち」にして、その日 10:00 のスタイルの枠で1件だけ擬似投稿します。

   ```powershell
   npm.cmd run dry-run -- --once --at 2026-10-05T10:00:00+09:00
   ```

   - `--` の後ろの部分がツールに渡されます。`--` を省かないでください。
   - `--at` を省くと、今の時刻で1回実行します（投稿枠の時刻でなければ擬似投稿はされません）。
   - SALON BOARD には何も送信しません。初期設定では AI も模擬（mock）なので、外部には何も送らず、費用もかかりません。模擬の AI の文章は動作確認用で、写真の内容は見ていません。
   - 擬似投稿した文章は `dry-run\data\history.json` に残り、次に作る文章との重複の検査に使われます。
   - `--at` に未来の日時を指定すると、その日時に擬似投稿した記録（最後に送信した時刻・その日の投稿枠・投稿済みのデータ）が dry-run のデータに残り、後で同じ dry-run のデータを使う実行（`npm.cmd start` や `--at` なしの dry-run）にも影響します。最後に送信した時刻が今より60分を超えて先の場合は、時計のずれとみなして送信間隔の判定には使わず、ログに注意を1回出します。
   - テストをやり直したいときは、ツールを止めた状態で `dry-run` フォルダを削除してください。次の実行で dry-run のデータが新しく作られ、pending の画像がもう一度取り込まれます（pending の元の画像と本番用のデータには影響しません）。

7. 状態を確認します。本日の投稿枠と、投稿データの数（擬似投稿したものは「投稿済み」）、AI の利用量と予算、テンプレート・公開トレンドの状態が表示されます。

   ```powershell
   npm.cmd run status
   ```

   - 投稿枠の数の意味：「完了」投稿した枠、「予約中」いま投稿している枠、「これから」この後の枠、「欠席」投稿できる画像（job）が無かった枠、「見送り」猶予時間を過ぎた・時間帯が終わった・上限に達したなどで使わなかった枠、「失敗」投稿に失敗した枠、「不足」目標のうち本日はもう投稿できない数（欠席・見送り・失敗や、時間が足りず作れなかった枠の合計）です。
   - 「失敗」した job は、job の id・理由・再開のコマンド（`npm.cmd run retry -- --id job_id`。job_id のところにその job の id が入ります）が一覧に出ます。画像を読み取れなかった job（`IMAGE_INVALID`）は再開できません。保存し直した画像を pending に入れると新しい job になります。dry-run では失敗の記録が残り続けるので、消したいときはツールを止めて `dry-run` フォルダを削除してください。

## 起動.bat で毎日使う（運用）

初回の準備が済んだら、毎日の操作は**このフォルダの `起動.bat` をダブルクリックするだけ**です。コマンドの入力は要りません。
`起動.bat` は、投稿をその場で一斉に送るボタンではありません。ツールを常駐させて、投稿の時間帯の外は待機し、投稿枠の時刻に1件ずつ処理します。`起動.bat` が勝手に本番（live）へ切り替えることはありません（`config\settings.json` の `"mode"` のとおりに動きます）。

### 初回準備

上から順に、最初に1回だけ行います（くわしくはそれぞれのリンク先を見てください）。

1. Node.js 24 LTS を入れます（[必要なもの](#必要なもの)）。
2. このフォルダで PowerShell を開き、部品を入れて、プログラムと拡張機能を組み立てます。

   ```powershell
   npm.cmd ci
   npm.cmd run build
   npm.cmd run build:extension
   ```

3. **AI のキー**：このフォルダの `.env` に `GEMINI_API_KEY=` に続けてキーを書きます（[AI の設定](#ai-の設定)の1・2）。dry-run を模擬の AI で動かすだけなら不要です。本物の AI を使う設定なのにキーが無いと、`起動.bat` は起動せずに書く場所を案内します（キーの値は画面にもログにも出しません）。
4. **お店のメニュー**：`config\salon.json` の `verified_menus` にお店のメニュー名を書きます（例：`"verified_menus": ["カット", "カット＋カラー"]`）。書くまで、スタイル投稿の写真は準備せずに待たせます。
5. **Excel のテンプレート**：`config\template_mapping.json` の `file_path` に Excel の場所を書きます（[テンプレート（Excel）の取込](#テンプレートexcelの取込)）。
6. 設定を検査します。「問題はありません」と出れば大丈夫です。

   ```powershell
   npm.cmd run config:validate
   ```

7. **拡張機能の読み込みと接続**：[本番投稿の準備](#本番投稿の準備salon-board-へ投稿する前に)の「4. 接続先を記録して、拡張機能を作って読み込む」と「5. ツールと拡張機能をつなぐ（接続）」を行います。手順5の `npm.cmd start` の代わりに `起動.bat` を使ってもかまいません（接続コードは `起動.bat` の黒い画面に出ます）。
8. **（任意）Chrome を一緒に開く**：`config\settings.json` の `"launcher"` に Chrome の場所と、SALON BOARD にログインしている Chrome のプロファイルを書くと、`起動.bat` がツールの起動後に Chrome を開きます。

   ```json
   "launcher": {
     "open_chrome": true,
     "chrome_path": "C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe",
     "chrome_profile_directory": "Default",
     "restart_limit": 3,
     "restart_window_minutes": 30
   }
   ```

   - `chrome_path` は、Chrome のアドレス欄に `chrome://version` と入力して出る「実行ファイルのパス」です。JSON では `\` を `\\` と2つ重ねて書きます。`chrome.exe` 以外のプログラムは開きません。
   - `chrome_profile_directory` は、同じ画面の「プロフィール パス」のいちばん最後のフォルダ名です（例：`Default`、`Profile 1`）。`null` のままなら、Chrome がふだん使うプロファイルで開きます。
   - `chrome_path` が `null`（初期値）のままなら Chrome は開かず、「Chrome はご自分で開いてください」と表示します。
   - `"open_chrome": "auto"` にすると、場所を書かなくても `chrome.exe` を探し（`chrome_path` を書けばそちら）、このツールの拡張機能が入っている Chrome のプロファイルを探して、SALON BOARD を開きます（`chrome_profile_directory` を書けばそちらが優先です）。見つからない・複数ある・Chrome が無いときは開かずに、黒い画面とログに理由を出します（ツールはそのまま動きます）。メンズとレディースの2つを使うときは、両方の `settings.json` をこの値にします。
   - ツールは Chrome のクッキーやパスワードを読まず、デバッグ用の接続も使いません。開いた Chrome でのログインはご自分で行います。
9. **本番で投稿するには**、[本番投稿の準備](#本番投稿の準備salon-board-へ投稿する前に)の1〜15をすべて行います。終わるまでは dry-run（テスト運転）か、準備の済んでいない投稿先には送らない状態で動きます。

### 日常運用

1. `起動.bat` をダブルクリックします。設定と準備を確かめてからツールが起動し、黒い画面に次のような表示が出ます（例）。

   ```text
   稼働モード: dry-run（テスト運転。SALON BOARD には投稿しません）
   次回投稿: スタイル 2026-10-05 10:33 ／ ブログ 2026-10-05 11:06
   拡張機能: 接続中
   送信を止めている理由: なし
   止めるには: このウィンドウで Ctrl+C を押すか、×で閉じます（投稿の途中だった1件は、次に起動したときに自動で確かめます）。
   ```

   - 「次回投稿」が「本日の予定なし」のときは、投稿の時間帯の外です。翌日の時間帯まで待機します。
   - 「送信を止めている理由」が出ているときは、その内容（ログイン・準備の未完了・一時停止など）を直します。dry-run のときは「本番にしたときに送信を止める理由」として出ます。dry-run の擬似投稿はそのまま進むので、本番にする前に直します。
2. 写真は4つの pending フォルダに入れます（[フォルダの説明](#フォルダの説明)）。
3. 黒い画面と Chrome は、開いたままにします（最小化してかまいません）。ツールが開く投稿用の専用ウィンドウは、投稿や確認の間だけ開き、終わると自動で閉じます。
4. ツールが動いている間は、パソコンが自動でスリープに入らないようにしています（Windows の設定は変えません。画面が消えるのは大丈夫です）。ただし、自分でスリープを選んだときや、ノートパソコンのふたを閉じたとき、電源が切れている間は投稿できません。ノートパソコンでは「ふたを閉じたときの動作」を「何もしない」にしておくと安心です。
5. 状態は、別の PowerShell で `npm.cmd run status`、または拡張機能のポップアップで確かめます。
6. `起動.bat` をもう一度ダブルクリックしても、2つ目のツールは起動しません。ほかの `起動.bat` の画面が開いているときは「起動.bat はすでに別のウィンドウで動いています」と出ます（そちらの画面を見てください）。`npm.cmd start` で起動したツールが動いているときは「ツールはすでに動作中です」と、いまの状態を表示します。どちらも、新しく開いた画面は閉じてかまいません。

`起動.bat` のおもな表示と対処です。

| 表示 | 意味と対処 |
|---|---|
| Node.js が見つかりません／Node.js のバージョンが合いません | Node.js 24 LTS（24.11 以上）を入れてから、もう一度ダブルクリックします |
| プログラムが組み立てられていません | 上の「初回準備」の2（`npm.cmd ci` と `npm.cmd run build`）を行います |
| 設定ファイルに○件の問題があります | 表示された「ファイル名 項目: 内容」の箇所を直して保存し、もう一度ダブルクリックします |
| AIのAPIキーが見つかりません | `.env` に表示された名前（例：`GEMINI_API_KEY=`）に続けてキーを書きます |
| データの保存先に書き込めません | フォルダが読み取り専用になっていないか、OneDrive などで同期中でないかを確かめます |
| 起動.bat はすでに別のウィンドウで動いています | もう1つの黒い画面を見てください。このウィンドウは閉じてかまいません |
| ツールはすでに動作中です | そのまま使えます（`npm.cmd start` で起動したツールのときも同じです） |
| 開始できません（PORT_IN_USE） | ほかのアプリが 3001 番のポート（`config\settings.json` の `server.port`。2つ目のツールは 3002 など）を使っています。そのアプリは終了させません。そのアプリを閉じるか、開発担当に相談してください |
| ツールが予期せず終了しました。10秒後に起動し直します | 自動で起動し直します（初期値は30分の間に3回まで） |
| 自動での起動し直しをやめました | `logs` フォルダのログを確認し、原因を直してから、もう一度ダブルクリックします。分からなければログを添えて開発担当に相談してください |
| Chrome を自動で開く設定（launcher.chrome_path）がまだ空です | Chrome をご自分で開きます（自動で開くときは「初回準備」の8） |

`起動.bat`（中で動く `node dist\src\launcher.js`。開発担当は `npm.cmd run launch` でも同じものを動かせます）の終了コードは、0 正常に止まった・すでに動作中、1 設定の誤り・AI のキーが無い、2 起動の前提が足りない（Node.js の版・組み立て・書き込み・ポート）・データを守るために止まった、3 予期しない終了が続いた、です。終わると画面を閉じずに「続行するには何かキーを押してください」（英語の Windows では「Press any key to continue . . .」）で待ちます（0 以外のときは「ツールが止まりました」も表示します）。

### 停止と再開

- **ツールを止める**：黒い画面で `Ctrl+C` を押します。処理中の1件を終えてから「停止しました。」と表示されます。続けて「バッチ ジョブを終了しますか (Y/N)?」（英語の Windows では「Terminate batch job (Y/N)?」）と聞かれたら、`Y` を押して Enter を押します。
  - ×で閉じる・パソコンの電源を切ると、処理の途中で止まることがあります。次に起動したとき、途中の処理を自動で確かめて復旧します（結果が分からない投稿は自動で送り直さず、照合します）。
- **もう一度動かす**：`起動.bat` をダブルクリックします。
- **投稿だけを一時停止する**（ツールは動かしたまま）：`npm.cmd run pause`（理由を残すときは `npm.cmd run pause -- --reason "臨時休業"`）。再開は `npm.cmd run resume` です。一時停止の間も、結果が分からない投稿の照合は続けます。
- **自動の起動し直し**：ツールが予期せず終了したときだけ、10秒待ってから起動し直します（`config\settings.json` の `launcher.restart_limit`（初期値3回）と `launcher.restart_window_minutes`（初期値30分））。`Ctrl+C` で止めたとき、設定の誤り、保存データの破損、ディスクの空きやメモリの不足、ポートが使えないときは、同じ原因で止まり続けるだけなので起動し直しません。

### Windows へのサインイン時に自動で起動する（タスク スケジューラ）

毎朝ダブルクリックする代わりに、Windows にサインインしたときに `起動.bat` を自動で実行できます（任意）。登録例は `docs/task-scheduler-sample.xml` です（サインインの1分後に起動、時間の制限なし、一般の権限、重なった起動は無視）。

1. スタートメニューで「タスク スケジューラ」を開きます。
2. 右側の「タスクのインポート...」を押し、このフォルダの `docs\task-scheduler-sample.xml` を選びます。
3. 開いた画面の「全般」タブで、「ユーザーがログオンしているときのみ実行する」が選ばれていることを確かめます（黒い画面を見られるようにするためです）。「最上位の特権で実行する」はオフのままにします。
4. 「トリガー」タブで「ログオン時」を選んで「編集」を押し、「特定のユーザー」（英語の表示では Specific user）を選んで、ご自分の名前になっていることを確かめます（読み込んだ直後は「すべてのユーザー」（Any user）になっています）。
5. 「操作」タブで「プログラムの開始」を選んで「編集」を押し、次の2つを**このフォルダの場所**に書き換えます。
   - 「プログラム/スクリプト」：このフォルダの `起動.bat`（例：`"C:\Users\<名前>\Documents\SalonTool\起動.bat"`。場所に空白があるときは前後を `"` で囲みます）
   - 「開始（オプション）」：このフォルダ（例：`C:\Users\<名前>\Documents\SalonTool`。`"` は付けません）
6. 「OK」を押して登録します。次にサインインしたときから自動で起動します。

- ダブルクリックとタスク スケジューラの起動が重なっても、ツールは1つしか動きません（2つ目は「すでに動作中」などと表示して終わります）。
- スリープからの復帰では起動しません（サインインしたときだけです）。
- やめるときは、タスク スケジューラの「タスク スケジューラ ライブラリ」で「SALON BOARD 自動投稿」を右クリックし、「無効」または「削除」を選びます。

### メンズとレディースを1つのフォルダで動かす

同じお店にメンズとレディースの2つの SALON BOARD のログインがあるときは、ツールを2つ（メンズ用・レディース用）用意して同時に動かします（1つのツールと1つの Chrome プロファイルは、1つのログインだけを扱います）。オーナーが触るものは1つの上のフォルダにまとめ、プログラムは `app` の中に置きます。

```
C:\自動投稿サロンボード\     ← 上のフォルダ（共通のフォルダ）
  ├ 起動.bat                ← これ1つで、メンズとレディースの両方が起動
  ├ 使い方.txt
  ├ .env                    ← AI のキー（OPENAI_API_KEY）と、2つのツールの接続用の値
  ├ images\pending\style\mens・blog\mens・style\ladies・blog\ladies   ← 写真を入れる所
  ├ 設定\                   ← 作業指示書.md・投稿先URL設定.md・件数とクーポン（メンズ／レディース）.txt など
  ├ トレンド語\             ← トレンド語一覧（メンズ／レディース）.xlsx・手動のトレンド語.xlsx
  └ app\
      ├ mens\               ← メンズ用のツール（このリポジトリ）
      └ ladies\             ← レディース用のツール（git clone したもの）
```

- 投稿中・失敗・投稿済みの写真（`images\processing`・`failed`・`posted`）、`data`・`logs`・`ledger`・`dry-run` は、それぞれのツールのフォルダ（`app\mens`・`app\ladies`）の中に別々に作られます。
- 共通のフォルダを使うかどうかは `config\settings.json` の次の項目で決まります（書かなければ今までどおり、すべてこのフォルダの中です）。

| 項目 | メンズ（`app\mens`） | レディース（`app\ladies`） | 意味 |
| --- | --- | --- | --- |
| `shared_root` | `"../.."` | `"../.."` | 共通のフォルダ（このフォルダから見た場所）。`.env`・`images\pending`・`設定`・`トレンド語` をそこで使います |
| `audiences` | `["mens"]` | `["ladies"]` | このツールが扱う対象。もう一方の写真・投稿先・トレンド語には触れません（`status` では「このツールでは扱いません」） |
| `server.port` | `3001` | `3002` | 2つのツールは別の番号にします（同じだと後から起動した方が `PORT_IN_USE` で止まります） |
| `server.token_env` | `"LOCAL_API_TOKEN"` | `"LOCAL_API_TOKEN_LADIES"` | 共通の `.env` の中で、拡張機能との接続用の値を書く行の名前（2つのツールで別にします。最初の起動で自動で書き込まれ、もう一方の行や AI のキーの行は消しません） |
| `server.allowed_extension_ids` | `["pfklebcmlgmehhghcphcdifbjelndlle"]` | `["mdeajimipobfmlnkjnbfhlmkbmfncbca"]` | 拡張機能のID。メンズとレディースの拡張機能は別のIDなので、2つの Chrome に1つずつ入れられます |
| `launcher.open_chrome` | `"auto"` | `"auto"` | `起動.bat` がそれぞれの拡張機能の入った Chrome を探して SALON BOARD を開きます |

- `設定` フォルダの読み方は今までの `instructions` フォルダと同じです（`README.md` と `.example.md` は読みません）。`作業指示書.md` などの内容は、2つのツールのどちらにも使われます。
- **件数とクーポン**：`audiences` が1つのツールは、`設定\件数とクーポン（メンズ）.txt`（レディースは `（レディース）`）の値を、`schedule.json` の `style_posts_per_day`・`blog_posts_per_day` と `salon.json` の `coupons` の代わりに使います。最初の起動で、いまの値でファイルを作ります。1行に1つ「名前: 値」で書きます（`#` の行は読みません）。

  ```
  スタイルの件数: 10
  ブログの件数: 10
  いつものクーポン: メンズカット¥6000
  クーポン・twist_spiral: メンズカット+スパイラルパーマ￥13000
  ```

  `クーポン・` の後ろは `categories.json` の `id` です。値に「なし」と書くと、そのクーポンは選びません。保存すると30秒ほどで反映されます。誤りがあると、直すまでファイル全体を使わず `config` の値で動き、`status` とログに理由が出ます（ファイルが無いときも `config` の値です）。
- **トレンド語**：それぞれのツールが自分の対象の `トレンド語一覧（メンズ）.xlsx`・`トレンド語一覧（レディース）.xlsx` を書きます（互いに上書きしません）。`手動のトレンド語.xlsx` は1つで、メンズのツールはシート「メンズ」、レディースのツールはシート「レディース」だけを読みます。

#### 作り方（最初の1回）

1. ツールを止めます。上のフォルダ（例：`C:\自動投稿サロンボード`）の中に `app` フォルダを作り、今のツールのフォルダの中身（`.git` を含む全部。上のフォルダが今のツールのフォルダと同じときは、`app` 以外の全部）を `app\mens` に移します。今の `images\pending` の中の写真は上のフォルダの `images\pending` へ、`instructions` の中のファイルは上のフォルダの `設定` へ、`トレンド語` は上のフォルダの `トレンド語` へ、`.env` は上のフォルダへ移します（`images` の `processing`・`failed`・`posted` と `data`・`logs`・`ledger` は `app\mens` に残します）。
2. `app\mens\config\settings.json` に上の表のメンズの値（`"shared_root": "../.."`・`"audiences": ["mens"]`）を書きます。
3. レディース用は**ファイルをコピーせず、`git clone` で作ります**（投稿の記録・接続のための秘密の値が混ざらないようにするためです）。`app` フォルダで PowerShell を開いて実行します。

   ```powershell
   git clone mens ladies
   cd ladies
   npm.cmd ci
   ```

   前の版で隣に `salon-ladies` フォルダを作ってあるときは、ツールを止めてそのフォルダを `app\ladies` に移し、`git -C app\ladies remote set-url origin` に続けて `app\mens` の場所を書いて実行してから（上のフォルダで実行します）、手順4に進みます（`salon-ladies\.env` の `LOCAL_API_TOKEN` の値は、共通の `.env` に `LOCAL_API_TOKEN_LADIES=` に続けて書くと、拡張機能の接続をやり直さずに済みます）。

4. `app\ladies\config\settings.json` に上の表のレディースの値（`shared_root`・`audiences`・`server.port`・`server.token_env`・`server.allowed_extension_ids`・`launcher.open_chrome`）を書き、`salon.json` の `expected_account_label` をレディースのログインの店舗名にします。
5. `app\ladies` でプログラムと拡張機能を組み立てます。拡張機能の名前は「サロン投稿アシスタント（レディース）」になります（メンズの `app\mens` でも `npm.cmd run build:extension` を実行すると「サロン投稿アシスタント（メンズ）」になります）。`allowed_extension_ids` が違うと、書くべきIDを表示して止まります。

   ```powershell
   npm.cmd run build
   npm.cmd run build:extension
   ```

6. 拡張機能は2つあり、Chrome のプロファイル（Google アカウント）ごとに1つずつ入れます。

   | Chrome（プロファイル） | SALON BOARD のログイン | 読み込むフォルダ | 拡張機能の名前 |
   | --- | --- | --- | --- |
   | メンズ用（いつもの Chrome） | メンズの店舗 | `app\mens\apps\extension\dist` | サロン投稿アシスタント（メンズ） |
   | レディース用 | レディースの店舗 | `app\ladies\apps\extension\dist` | サロン投稿アシスタント（レディース） |

   レディース用のプロファイルが無ければ、Chrome の右上のプロフィールのアイコンから「追加」で作ります。それぞれの Chrome で `chrome://extensions` から上のフォルダを読み込みます（前の版の拡張機能（名前に（メンズ）・（レディース）が付かない「サロン投稿アシスタント」）が残っていれば削除します）。`launcher.open_chrome` を `"auto"` にしておくと、`起動.bat` が2つのツールと、それぞれの拡張機能が入った Chrome を開きます。拡張機能を違う Chrome に入れたとき（別の店舗でログインしている Chrome）は、ポップアップと `status` に「この Chrome は「（ログイン中の店舗名）」でログインしています。この拡張機能は（メンズ）用です。…」と出て、投稿しません。案内のとおりに入れ直してください。
7. `app\ladies` で「[本番投稿の準備](#本番投稿の準備salon-board-へ投稿する前に)」を行います（接続・画面の調査・確認済みの記録など。コマンドは `app\ladies` の PowerShell で実行します）。`設定\投稿先URL設定.md` にはメンズとレディースの両方の行を書きます（それぞれのツールは自分の対象の行だけを使います）。
8. `app\mens` の PowerShell で `npm.cmd run layout:sync` を実行すると、上のフォルダに `起動.bat`・`使い方.txt`・`Mac用に書き出す.bat` が書き込まれます（違うときだけ。`.env`・`images`・`設定`・`トレンド語` には触れません）。
9. 毎日は、上のフォルダの **`起動.bat`** をダブルクリックします。2つのツールがそれぞれの黒い画面で起動します（黒い画面の題名にフォルダ名が出ます）。片方だけ動かすときは、`app\mens` か `app\ladies` の `起動.bat` を使います。サインイン時の自動起動（[タスク スケジューラ](#windows-へのサインイン時に自動で起動するタスク-スケジューラ)）で2つとも起動するときは、手順5の「プログラム/スクリプト」を上のフォルダの `起動.bat` にします。

#### レディース用を新しい版にする

メンズ用（`app\mens`）を新しい版にしたら、`app\mens` の PowerShell で次を実行します。

```powershell
git -C ..\ladies pull
```

`git pull` が「local changes would be overwritten」で止まったときは（`app\ladies\config` の設定を書き換えているため）、代わりに `git -C ..\ladies pull --autostash` を実行します（書き換えた設定はそのまま残ります。ぶつかったと出たときは開発担当に連絡してください）。

`package-lock.json` が変わったときは、`app\ladies` で `npm.cmd ci` を実行します。続けて `app\ladies` で `npm.cmd run build` と `npm.cmd run build:extension` を実行し、Chrome（レディース用のプロファイル）の `chrome://extensions` で拡張機能の再読み込みボタンを押します。`起動.bat` や `使い方.txt` が変わったときは、`app\mens` で `npm.cmd run layout:sync` を実行します。

### Mac で使う

Windows の版はそのまま残し、Mac 用は「書き出した zip」を MacBook に移して使います（Mac 用のファイルは `layout/mac/`）。

**Mac のフォルダ**（おすすめはホームの `~/SalonBoard`。iCloud で同期される「書類」「デスクトップ」は避けます。どこに置いても、各ファイルは自分の場所から動きます）

```text
~/SalonBoard/
  起動.command        ← ダブルクリックで準備と起動（メンズ・レディースを別々のターミナルで）
  使い方.txt          ← Mac 用の使い方（layout/mac/使い方（Mac）.txt）
  bin/salonboard      ← どこからでも使えるコマンド
  .env  images/pending  設定  トレンド語   ← Windows の共通フォルダと同じ
  app/mens  app/ladies                    ← それぞれ起動.command と .package-id 付き
  .runtime/           ← Mac で作られる（Node.js 24、setup.log、組み立ての印）
```

**書き出し（引っ越しの日、Windows で）**: 黒い画面を2つとも閉じてから、共通のフォルダの **`Mac用に書き出す.bat`** をダブルクリックします（`app\mens` の `npm.cmd run export:mac` と同じ）。デスクトップに `SalonBoard-Mac-YYYYMMDD-HHmm.zip` ができ、Windows の2つのツールは一時停止します（二重投稿を防ぐため。やめるときは各フォルダで `npm.cmd run resume`）。ツールが動いている間は書き出しません。`npm.cmd run export:mac -- --check` は中身と大きさを表示するだけです（書き出しも一時停止もしません）。

- zip に入るもの: 上の Mac のフォルダの中身と、各ツールのフォルダから `node_modules`・`dist`・`apps/extension/dist`・`tests`・`docs`・`.git`・`dry-run` と動作中の印（`data/app.lock`・`data/launcher.lock`・`data/local-api.json`）を除いたもの（`data`・`ledger`・`logs`・`images` の記録はそのまま移ります）。
- テンプレートの Excel（`template_mapping.json` の `file_path`。Windows の場所）は `設定` に写し、zip の中の `template_mapping.json` だけを `../../設定/<ファイル名>` に直します（Windows のファイルは変えません）。
- 拡張機能との接続（`data/pairing.json`）は、zip の中だけ「未接続」にします。Mac の初回の起動で各ウィンドウに接続コードが出るので、Mac の Chrome の拡張機能で接続し直します。

**初回の起動（Mac）**: zip をホームで展開し、`起動.command` を右クリック >「開く」で開きます（Gatekeeper のため最初の1回だけ）。macOS 15 以降で「完了」しか出ないときは、システム設定 > プライバシーとセキュリティ の「このまま開く」を押します（それでも開けないときは、ターミナルで `bash ~/SalonBoard/起動.command`）。zip は USB メモリで移すのがおすすめです（AirDrop で移すと隔離の印が付きます）。インターネットが必要です。次を自動で行います（管理者のパスワード・Homebrew は不要）。

1. フォルダの隔離の印（`com.apple.quarantine`）を外す。
2. Node.js 24（24.11 以上）が無ければ、nodejs.org の公式版を Mac の種類（arm64 / x64）に合わせて `SHASUMS256.txt` で確かめてから `.runtime/node` に入れる。
3. Google Chrome が無ければ、ダウンロードのページを開いて止まる（入れてから開き直す）。
4. 各ツールで、`node_modules` が無いか `package-lock.json` が変わったときは部品のインストール（npm ci）、組み立てが無いか `.package-id` が変わったときはプログラムと拡張機能の組み立て（build・build:extension）。
5. `~/.zprofile`（あれば `~/.bash_profile` も）に `bin` を PATH に足す1行を書く（新しいターミナルから `salonboard` が使えます）。
6. メンズとレディースをそれぞれのターミナルで起動する。

Chrome は2つのプロファイル（メンズ・レディースのログイン）を作り、それぞれに `app/mens/apps/extension/dist` と `app/ladies/apps/extension/dist` を読み込んで、各ウィンドウの接続コードで接続します。

**salonboard コマンド**: `salonboard start`（起動）、`salonboard status`（両方の状態）、`salonboard mens <コマンド>`・`salonboard ladies <コマンド>`（例: `salonboard mens pause`、`salonboard ladies retry --id <番号>`。npm のスクリプトと同じ名前）、`salonboard help`。

**Windows との違い**: 画面の命令は `npm.cmd` ではなく `npm`、`起動.bat` ではなく `起動.command` と表示されます。スリープは `caffeinate` で防ぎますが、ふたを閉じるとスリープします（外部ディスプレイにつないだクラムシェルモードを除く）。`launcher.open_chrome` は `"auto"` のときだけ Mac の Chrome を探して開きます。フォルダの権限の確認（icacls）は行いません。拡張機能のポップアップの案内には `npm.cmd`・PowerShell の表記が残ります。

**Windows と Mac のツールを同時に動かさないでください**（同じ店舗に二重に投稿されます）。

### 障害対応

1. 黒い画面の表示と `npm.cmd run status` の「送信を止めている理由」「対処」で原因を確かめます（拡張機能のポップアップにも同じ内容が出ます）。
2. ログイン・画像・設定・ディスクの空きなど、原因を直します。
3. 結果が分からない投稿があれば、先に `npm.cmd run reconcile` で照合します（SALON BOARD の投稿一覧で確かめた結果を記録します）。
4. 必要な job を `npm.cmd run retry` で再開します。
5. `npm.cmd run resume` で送信を再開します。

| 起きたこと | 対処 |
|---|---|
| ツールが起動しない・すぐ止まる | 黒い画面の表示（上の表）と、`logs` フォルダのその日のログ（`app-日付.jsonl`）を確かめます |
| `STATE_CORRUPT`（保存データの破損） | データを守るために止まっています。`data\` のファイルを手で直さず、ログを添えて開発担当に相談してください |
| `LOCK_CONFLICT`（ほかに動作中） | `npm.cmd start` や保守用のコマンドが動いていないか確かめ、止めてから起動します。強制終了の後に残った印は、次の起動で自動で引き継ぎます |
| `DISK_FULL`・`RESOURCE_DISK_LOW`（ディスクの空き不足） | 不要なファイルを消して空きを作り、起動し直します。投稿済みのデータは下の「30日整理」で自動で減ります。終わっていない投稿のデータは、空きを作るためにツールが消すことはありません |
| `RESOURCE_MEMORY_HIGH`（メモリ不足） | 新しい処理を止めています。ほかのアプリを閉じ、続くときはツールを止めてから起動し直します |
| 拡張機能が「未接続」のまま | Chrome が開いているか、ポップアップの表示を確かめます（[安全のための設定](#安全のための設定)の「Chrome がツールへ接続できないとき」） |
| ログインが切れた | Chrome で SALON BOARD にご自分でログインし直し、`npm.cmd run resume` を実行します（ツールは自動でログインしません） |

- 画像を手で pending に戻さないでください。同じ写真の job が2つできる原因になります（失敗したものは `retry` で再開します）。
- 本番での詳しい流れは[困ったとき（本番）](#困ったとき本番)、コマンドの終了コードは[終了コード](#終了コード)を見てください。

### 30日整理

投稿が済んだ（SALON BOARD で登録を確かめた）データのうち、**このパソコンの中のもの**だけを、成功を確かめてから30日（`config\settings.json` の `retention.posted_data_days`）を過ぎたら自動で整理します。

- **整理するもの**：その投稿の画像（取り込んだ写真の控え・添付用に作った画像）、タイトルと本文の全文、写真の解析の詳細、登録を確かめた記録（evidence）。
- **整理しないもの**：SALON BOARD に公開した投稿と画像（ツールは SALON BOARD の投稿を消しません）、`config`・`instructions`・Excel・トレンドの CSV、お店が別の場所に保存した元の写真、終わっていない投稿（投稿待ち・失敗・結果不明など）、重複を防ぐための記録（`data\dedupe.json`。30日を過ぎても同じ写真・同じ文章を二度投稿しないために残します）、送信の記録（`ledger\`）。
- **いつ**：起動したときと、その後は24時間ごとに、少しずつ（20件ずつ）整理します。パソコンを止めていた間の分は、次に起動したときに整理します。整理のたびの承認は要りません。
- **確かめる**：`npm.cmd run cleanup:preview` で、整理の対象の件数・容量と、対象にしない理由を表示します（何も消しません）。
- **すぐに整理する**：`npm.cmd run cleanup`（ツールの動作中は、動作中のツールに頼みます）。
- 元の写真を長く残したいときは、pending に入れる**前に**、別の場所へコピーしておいてください。
- ログ（`logs\`）は30日・1ファイル20MB・全体512MB、バックアップは30日・合計1024MBを上限に、古いものから整理します（`config\settings.json` の `logs`・`retention`・`resources`）。

## 普段の使い方

ふだんは上の `起動.bat` を使います。`npm.cmd start` でも同じように常駐します（`起動.bat` は、その前に準備を確かめ、予期しない終了のときに起動し直し、Chrome を開きます）。

- **常駐させる**：`npm.cmd start`
  10秒ごとに画像フォルダを確認して取り込み、投稿の準備（AI による解析・文章の作成・検査）をし、30秒ごとに投稿枠を確認します（dry-run では擬似投稿）。画面に出来事が日本語で表示されます。
  - 本番（live）では、Chrome 拡張機能が30秒ごとにツールへ問い合わせ、投稿枠の時刻になった1件を、投稿用の専用ウィンドウで SALON BOARD に登録して、登録できたかを確かめます（「本番投稿の準備」が済んだ投稿先だけ）。
  - 投稿の準備は1件ずつ進め、1件ごとに投稿枠を確認します。枠の時刻になったときにその種類（スタイル／ブログ）の画像を準備中なら、猶予時間（schedule.json の slot_grace_minutes）の間は準備ができるのを待ち、その種類の準備を先に進めます。
  - AI の通信が一時的にうまくいかないとき（混雑・時間切れ・接続できない）は、その写真を失敗にせず、1分・5分・15分と間をあけてやり直します。3回やり直しても直らなければ「失敗」にします（`retry` で再開できます）。
  - 予算の上限・API キーの誤り・AI の設定の誤りのときは、すべての写真の準備を止め（AI を呼びません）、`status` に理由を表示します。予算は翌日（日本時間0時）か予算を増やすと、設定の誤りは `settings.json` を直すと、自動で再開します。`.env` の API キーを直したときは、ツールを起動し直してください。
  - Excel のテンプレート・公開トレンドの CSV は、30秒ごとに変わっていないかを確かめ、変わったときだけ読み直します。
  - 設定（`keywords.json` の除外語など）や作業指示書（検索ワード・除外検索ワード・文章方針）が変わると、投稿待ちの文章を今の決まりでもう一度検査し、通らなくなったものは作り直します（まだ投稿に使われていないものだけ）。
- **止める**：そのウィンドウで `Ctrl+C` を押します。処理中の1件を終えてから止まり、「停止しました。」と表示されます。
  - コマンドプロンプト（`cmd.exe`）などで、その後に「バッチ ジョブを終了しますか (Y/N)?」（英語の Windows では「Terminate batch job (Y/N)?」）と聞かれることがあります。ツールはすでに止まっているので、`Y` を押して Enter を押してください。
- **状態を見る**：別の PowerShell ウィンドウで `npm.cmd run status`。読み取るだけで、何も変更しません（動作中でも使えます）。
  - 「SALON BOARD への投稿」の欄に、いま投稿できるか（できないときはその理由すべて）、本日の種類ごとの成功・予約（うち結果不明）・不足・次回・残り件数、投稿先ごとの設定・画面の確認・初回投稿の状態とURL（`?` から後ろの値は表示しません）、Chrome 拡張機能の接続とログインの要否、対応が必要な作業、本番の準備で未完了の項目、注意が出ます。ツールの動作中は、動作中のツールに聞いた内容を表示します。拡張機能のポップアップにも同じ内容（要点）が出ます。
  - 「【重要】投稿の配布を止めています（STATE_CORRUPT または FILE_IO_ERROR）」と出たら、途中で止まった画像の移動を自動では直せなかったため、投稿を止めています。表示された job について `images\failed`（dry-run では `dry-run\images\failed`）とログ（`logs` フォルダ）で原因を確認し、原因を取り除いてからツールを再起動してください。
    - job ごとの行には、その job 自身の理由（`FILE_IO_ERROR` か `STATE_CORRUPT`）が出ます。理由が混在しているときは、全体の分類（1件でもファイルの読み書き以外の原因があれば `STATE_CORRUPT`）を「※」の行で示します。
  - この表示は、動作中のツールが `data\runtime-status.json`（dry-run では `dry-run\data\runtime-status.json`）に書く記録をもとにしています。
  - 「前回の稼働は強制終了されたようです（…以降の記録がありません）」と出たら、前回のツールは `Ctrl+C` で止めずに終了しています（ウィンドウを閉じた・パソコンの電源が切れた など）。次に起動すると、途中で止まった処理を自動で確認・復旧します。
  - 保存データが壊れている・読み取れないときは、「状態を表示できません（STATE_CORRUPT）」または「状態を表示できません（FILE_IO_ERROR）」と出て、終了コード 2 で終わります（下の「終了コード」）。
  - **設定ファイルにいま誤りがあると、`status` は状態の代わりに設定の誤りの場所を表示し、終了コード 1 で終わります。** 表示されたファイルを直して保存し、もう一度実行してください。
- **設定を変える**：`config` フォルダのファイルをメモ帳などで編集して保存します。動作中なら30秒以内に読み直し、誤りがあれば反映せずに直前の正しい設定のまま動き続けます（`status` に誤りの場所が出ます）。投稿件数などを変えた場合は、本日のこれからの枠だけが組み直されます。
  - 投稿の予定（`schedule.json`）やその他の設定は、30秒ごとの読み直しで自動的に反映されます。本日の時間帯や件数に関係しない変更では、本日の枠は組み直しません。
  - **`settings.json` の `"logs"` の `"level"`（ログの詳しさ）・`"mode"`・`"data_root"`、`salon.json` の `salon_id`、`.env` を変えた場合は、いったん止めてから起動し直してください。** 再起動するまで反映されません。`salon.json` の `verified_menus` などそのほかの項目は、30秒ごとの読み直しで反映されます。
- **作業指示書で変える**：`instructions` フォルダに Markdown（`.md`）の指示書を置くと、JSON を編集せずに営業時間・臨時休業・投稿時間・検索ワード・文章方針・投稿先URLを変えられます。書き方は `instructions\README.md` を見てください。
  - 動作中は30秒ごとにフォルダを確認します（保存の途中のファイルがあれば、数秒後にもう一度確認します）。営業時間・投稿時間・臨時休業の変更で本日の時間帯が変わったときは、本日のこれからの枠だけが組み直されます。投稿済みの枠は変わりません。
  - `npm.cmd run status` の「作業指示書」に、適用中の指示書・反映した営業時間と重点語・投稿数を減らす曜日（指示書の営業時間・投稿時間に1日の投稿数が入りきらない曜日。時間は守り、件数を減らします）・今後14日間で投稿しない日・反映していない指示とその理由が出ます（`status` はフォルダを読み直して表示し、何も書き換えません）。本日の計画を作った後に指示書や設定で本日の時間帯が変わったときは、次の確認で組み直した後の見込みで枠を表示します。
  - 起動時に `instructions` フォルダを確認できなかったときは、確認できるまで投稿の配布を待ちます（画像の取込と準備は続けます）。
- **保守用のコマンド**（`templates:import`・`trends:refresh`・`history:rebuild`・`ai:smoke`・`ai:test`）は、**ツールを止めてから**実行してください（`retry`・`redraft`・`pause`・`resume`・`reconcile` は動作中でも使えます）。動作中のツールと同じファイルを書き換えるため、動作中は「ツールが動作中…のため実行できません」と表示して何もしません（終了コード 2）。
- **AI のサービスやモデルを変える**：`.env` を編集して保存し、`npm.cmd run ai:test` で試してから起動し直します（下の「AI の設定」の6）。

## 本番投稿の準備（SALON BOARD へ投稿する前に）

本番投稿は、次の1〜15がすべて終わるまで始まりません。上から順に進め、分からないところがあればその手順で止めて開発担当に相談してください。

- **オーナー（店舗の方）が行うこと**：SALON BOARD の運営・契約での確認、件数やログイン条件の確認と記録（`checks:record`）、Chrome でのログイン、投稿画面のURLの貼り付け、画面の調査、試し投稿の承認と実行。
- **開発担当（AI を含む）が行うこと**：画面の調査結果から「画面設定（profile）」を作り、オーナーが打つコマンドを用意します。開発担当が SALON BOARD を開いたり、URL を書いたり、記録のコマンド（`checks:record`）や本番投稿（`live:single`）をオーナーの代わりに実行したりすることはありません。
- 記録の内容はいつでも `npm.cmd run checks:record -- show` で確認できます。まだ記録していない項目には、記録のしかたが表示されます。記録するたびに `config` フォルダの設定ファイルが書き換わり、変更の前後が表示されます。日付は実際に確認した日を書きます（未来の日付は記録できません）。
- 下のコマンドの数字や文は**例**です。必ずご自分で確認した内容に置き換えてください。

### 1. 自動操作の可否を確認する

SALON BOARD の利用規約・契約書類、または運営への問い合わせで、「自作のブラウザ拡張機能で SALON BOARD への投稿を自動化してよいか」を確認します。

- 許可されているとき（`--evidence` には文書名と版・確認日・該当箇所、または運営の回答の要約を書きます）：

  ```powershell
  npm.cmd run checks:record -- automation --status permitted --evidence "利用規約 第○条（2026年○月版）／運営からの回答メール" --checked-at 2026-10-10
  ```

- 禁止されているとき：`--status prohibited` で同じように記録します。ツールは投稿用のデータ（文章と画像）の準備までで止まり、SALON BOARD の画面は開きません（画面の調査もしません）。投稿は手動で行ってください。
- 分からない間は記録しないでください。「未確認」のままでは、本番投稿も、ツールが画面を開く確認（下の10・11）もしません。

### 2. 投稿数の上限と今の件数を記録する

SALON BOARD の画面やヘルプで、スタイル・ブログそれぞれの上限（1日・1か月・累計・画像の容量）を確認して記録します。

```powershell
npm.cmd run checks:record -- limit --type style --kind daily --status limited --value 10 --unit 件 --source "SALON BOARD のヘルプ" --checked-at 2026-10-10
npm.cmd run checks:record -- limit --type style --kind monthly --status unlimited --source "SALON BOARD のヘルプ" --checked-at 2026-10-10
npm.cmd run checks:record -- limit --type style --kind total --status limited --value 300 --unit 件 --source "掲載管理の画面" --checked-at 2026-10-10
npm.cmd run checks:record -- limit --type style --kind image_capacity --status not_applicable --reason "画像の容量の上限の記載なし"
npm.cmd run checks:record -- count --type style --kind total --value 120 --at "2026-10-10 09:00"
npm.cmd run checks:record -- margin --type style --value 2 --valid-days 7
npm.cmd run checks:record -- boundary --type style --value jst_calendar
```

- 4種類（`daily`・`monthly`・`total`・`image_capacity`）すべてを、上限あり（`limited`）・上限なし（`unlimited`）・当てはまらない（`not_applicable`）のどれかで記録します。**1つでも分からない項目があると、その種類（スタイル／ブログ）は本番送信しません。**
- 上限がある種類があるときは、上限までに残しておく件数（`margin`）も記録します。1日・1か月の上限は、日本時間の0時・1日で区切って数えるとき `boundary --value jst_calendar` を記録します（区切り方が違うときは記録せず、開発担当に知らせてください）。累計の上限があるときは、今の掲載件数（`count --kind total`）と、その件数を使ってよい日数（`margin` の `--valid-days`）も記録します。
- ブログも同じように `--type blog` で記録します。
- **手動の投稿や、ほかの端末からの投稿は、記録した件数と余裕（`margin`）でしか考慮できません。** 手動で投稿した日は、今日・今月の件数を `count --kind daily` / `count --kind monthly` で記録し直すと正確になります。
- 計算上上限に達した日は、その種類の残りの枠を見送り、翌日（翌月）に自動で再開します。画面に「上限に達した」と出たときは、その種類の送信を止めて `status` で知らせます。

### 3. ログイン・2段階認証・同時ログインを確認して記録する

```powershell
npm.cmd run checks:record -- auth --checked-at 2026-10-10 --mfa "なし" --session "約○時間でログアウト（ヘルプの記載）" --concurrent "別の端末でログインすると前の画面はログアウトされる"
```

- ツールはパスワードを扱わず、自動でログインもしません。ログインが切れていると、送信を止めて `status` とポップアップで知らせます。
- **投稿中は、同じ SALON BOARD を別のタブや別の端末で操作しないでください（ログインが切れたり、画面が変わる原因になります）。**

### 4. 接続先を記録して、拡張機能を作って読み込む

1. Chrome で SALON BOARD に手動でログインし、アドレス欄のURLをコピーして記録します（記録されるのは `https://…` のサイトの部分だけです）。

   ```powershell
   npm.cmd run checks:record -- origin --url "（コピーしたURL）"
   ```

2. 拡張機能を作ります。`apps\extension\dist` フォルダができます。

   ```powershell
   npm.cmd run build:extension
   ```

3. Chrome のアドレス欄に `chrome://extensions` と入力して開き、右上の「デベロッパー モード」をオンにして、「パッケージ化されていない拡張機能を読み込む」から `apps\extension\dist` フォルダを選びます。作り直したとき（`build:extension` をもう一度実行したとき）は、一覧の「サロン投稿アシスタント（メンズ）」（レディース用は「（レディース）」。名前は `settings.json` の `audiences` で決まります）の丸い矢印（再読み込み）を押します。
4. 「サロン投稿アシスタント（メンズ）」の「詳細」→「サイトへのアクセス」で、SALON BOARD へのアクセスが許可されていることを確認します。
5. ツールバーのパズルの形のアイコンから「サロン投稿アシスタント（メンズ）」をピン留めしておくと、ポップアップを開きやすくなります。

- 接続先が変わったときは、1〜3をやり直します。

### 5. ツールと拡張機能をつなぐ（接続）

1. `起動.bat`（または `npm.cmd start`）でツールを起動します（すでに動いていれば、その黒い画面を使います。このときはまだ `"mode"` は `"dry_run"` のままです）。黒い画面に「拡張機能の接続コード: XXXXX-XXXXX」が出ます（5分間有効。長い状態の表示の下にも、もう一度出ます）。期限が切れたときは、ポップアップの「接続」を押すと新しいコードが黒い画面に出ます。
2. 拡張機能のポップアップの「接続」を押し、「接続コード」の欄にそのコードを入力して「送信」を押します。
3. **黒い画面とポップアップの両方に、同じ「確認記号」（例：AB12）が出ていることを確認します。** 違う記号が出たときは、使わずに開発担当に相談してください。

- 接続コードは他人に教えないでください。接続し直すときは、ツールの動作中に別の PowerShell で `npm.cmd run pair` を実行し、表示されたコードをポップアップの「接続コード」の欄に入力して「送信」を押します（新しい接続ができた時点で、前の接続は使えなくなります）。
- 接続は dry-run と本番で共通です。`"mode"` を切り替えて起動し直しても、接続し直す必要はありません。

### 6. SALON BOARD に手動でログインしておく

- Chrome で SALON BOARD にログインしたままにします。
- ツールは投稿や確認のたびに、タブが1つだけの専用の Chrome ウィンドウを開き、終わると自動で閉じます（ほかに Chrome のウィンドウが無いときは、Chrome ごと終わらないよう閉じずに残し、次の投稿で使います）。**開いている間は閉じずに、そのままにしてください**（最小化や、ほかのウィンドウの後ろにあってもかまいません）。

### 7. 投稿先URLを書く

1. `instructions\投稿先URL設定.md` をメモ帳で開きます。
2. Chrome で4つの投稿画面（スタイル・メンズ、スタイル・レディース、ブログ・メンズ、ブログ・レディース。それぞれ新しく登録するときの入力画面）を順に開き、**アドレス欄のURLをコピーして**、該当する行の「:」の右に貼り付けます。
   - URLは推測で書かないでください。必ず画面のアドレス欄からコピーします。
   - 男女で同じ画面（画面の中で「メンズ／レディース」を選ぶ）ときは、同じURLを両方の行に貼ります。投稿しない組み合わせは空欄のままにします（その組み合わせには投稿しません）。
3. 「状態: 無効」を「状態: 有効」に書き換えて保存します。
4. `npm.cmd run status` の「投稿先」で、その投稿先が「設定あり（指示書）」になっていることを確かめます（URL は、`?` から後ろの値を消した形で表示します）。

### 8. 画面を調査する（入力も登録もしません）

1. 投稿画面を開き、**お客様の名前・電話番号などが映っていないこと**を確認します。
2. 拡張機能のポップアップの「画面を調査」で確認のチェックを入れ、「入力画面（投稿フォーム）」を押します。4つの投稿画面それぞれで行います。
3. ふだんどおり手動で1件投稿したあとの「完了の画面」と「投稿の一覧の画面」でも、一覧に出ている投稿のタイトルを1つそのまま入力して「完了・一覧の画面」を押します（ブログは「確認する」を押した後の確認の画面でも行います）。
4. 保存された調査結果を確認します。

   ```powershell
   npm.cmd run survey:list
   npm.cmd run survey:show -- --file ファイル名
   ```

   「ファイル名」は survey:list に出た名前に書き換えます。お客様の情報が入っていなければ、`--approve` を付けてもう一度実行します（`npm.cmd run survey:show -- --file ファイル名 --approve`）。承認したファイル名を開発担当に伝えます。

- 調査結果はこのパソコンの `data\survey` にだけ保存されます。入力欄の値・クッキー・ログイン画面は保存しません。開発担当は、オーナーが承認したファイルだけを読みます。

### 9. 開発担当が画面設定を作る（相談しながら）

開発担当は、承認された調査結果から4つの投稿先の画面設定（profile）を作り、次のことをオーナーに確認します。

- 店舗名の表示（画面の上に出る店舗名）と、選ぶスタイリスト名・投稿者
- ツールのカテゴリーを、SALON BOARD のどのカテゴリーに対応させるか
- 「登録」を押した後に、確認の画面や小さな確認の窓が出るか
- ハッシュタグの欄の使い方
- 「長さ」など、ツールが知らない必須の項目を、決まった値にするか、画像の解析結果から選ぶか

開発担当は `npm.cmd run profile:check` で調査結果と画面設定を照らし合わせ、問題がなくなったら、画面設定の「確認記号」（英数字64文字。すべての項目が OK のときだけ表示されます）と、オーナーが実行するコマンドを伝えます。

**クーポン**：スタイルでは、`salon.json` の `coupons` に書いたクーポン名で、クーポンの選択画面から1つ選びます。写真の補足情報（`sidecar.json` の `category_hint`）で確認したカテゴリーが `by_category` にあればそのクーポン、なければ `default` を選びます（名前は画面の表示と同じに。空白・全角半角の違いは無視します）。画面に同じ名前のクーポンが見つからないときは、クーポンなしで投稿を続けます。

```json
"coupons": { "default": "メンズカット¥6000", "by_category": { "twist_spiral": "メンズカット+スパイラルパーマ￥13000", "mens_perm": "メンズカット+ニュアンスパーマ￥11000", "twist": "メンズカット+ニュアンスパーマ￥11000" } }
```

**スタイルの公開（反映申請）**：SALON BOARD では、登録したスタイルは「反映申請」を押すまで公開されません。スタイルの画面設定に `publish` を書くと、登録を画面で確認できた直後に、掲載管理TOPの「反映申請」を自動で押します。反映申請はほかの未公開の変更もまとめて公開します。押せなかったときは、ログに警告を残すだけで投稿の結果は変わらず、次のスタイル投稿の反映申請でまとめて公開されます。スタイルの画面設定に追加する例：

```json
"publish": { "url": "https://salonboard.com/CNB/reflect/reflectTop/", "url_match": { "origin": "https://salonboard.com", "paths": ["/CNB/reflect/reflectTop/"] }, "button": [{ "css": "button#reflectedButton" }], "done_url_match": { "origin": "https://salonboard.com", "paths": ["/CNB/reflect/storeReflect/doRegister/", "/CNB/reflect/reflectTop/"] } }
```

### 10. 画像の添付を確かめる（登録しません）

開発担当と日時を決めて行います。

1. ツールの動作中に、別の PowerShell で `npm.cmd run probe -- --arm --yes` を実行します（10分間だけ受け付けます）。
2. 投稿画面（新しく登録する入力画面）を開き、ポップアップの「登録ボタンは押さず…」にチェックを入れて「画像添付の確認（登録しません）」を押します。テスト用の画像（灰色の市松模様）が画像の欄に入り、プレビューが出るかを確かめます。
3. **登録ボタンは押さず**、確認が終わったらその画面は登録せずに閉じます。テスト用の画像が一時的に SALON BOARD に送られる場合があります。

### 11. 画面を確認する（入力も登録もしません）

```powershell
npm.cmd run preflight -- --route configured
```

ツールが投稿用のウィンドウで設定済みの投稿画面を開き、ログイン・店舗名・画面・入力欄・登録ボタンを確かめて、投稿先ごと・確認ごとに「OK／NG」を表示します（最大90秒）。入力・画像の添付・登録はしません。NG のときは表示された内容を開発担当に伝えます（画面設定を直して、もう一度9から）。1つの投稿先だけを確かめるときは `--route style.mens` のように指定します。

### 12. 画面設定を確認済みにする

画面が設定どおりだと確かめられたら、開発担当が示すコマンドを実行します（例）。

```powershell
npm.cmd run checks:record -- profile --id style_mens --hash "<profile:check が表示した確認記号>"
npm.cmd run checks:record -- route --type style --audience mens --verified true
```

- 画面設定を少しでも直すと確認記号が変わり、確認済みでなくなります（`status` の「画面: 確認後に変更あり」）。そのときは11と12をやり直します。

### 13. dry-run で流れを確かめる

`"mode"` が `"dry_run"` のまま、`npm.cmd run dry-run -- --once` や `npm.cmd start` で、画像の取込から擬似投稿までを確かめます（SALON BOARD には送りません）。

### 14. 本番モードにして、投稿先ごとに初回の1件だけを投稿する

1. 本物の AI の設定（上の「AI の設定」）を済ませ、`config\settings.json` の `"mode"` を `"live"` にして保存し、ツールを起動し直します（拡張機能の接続はそのまま使えます）。
2. `npm.cmd run status` で「本番の準備で未完了の項目はありません」と、使う投稿先ごとに「初回投稿: live:single 待ち」が出ていることを確かめます。
3. 開発担当と日時を決めて、**投稿先ごとに1件ずつ**行います。まず内容を表示します（まだ何も予定しません）。

   ```powershell
   npm.cmd run live:single -- --route style.mens
   ```

   「この内容で1件だけ本番投稿します。」に続いて、投稿先・job の番号・タイトル・文章の始め・カテゴリー・画像・投稿先のURLが表示されます。**内容がよければ、同じコマンドに `--yes` を付けて実行します。**

   ```powershell
   npm.cmd run live:single -- --route style.mens --yes
   ```

   表示した1件だけを次の投稿枠で本番投稿し、終わると自動で一時停止します。一時停止中に予定したときは、`npm.cmd run resume` を実行するとその1件だけを送信します。表示した後に文章や画像が変わったときは `--yes` が断られるので、`--yes` なしからやり直します。
4. SALON BOARD の画面で、登録された内容を確かめます：画像1枚、特集なし、「画像を応募する」はオフ、モデル情報は写真から選んだ内容（自信がない項目は「設定しない」）、クーポンは写真のカテゴリーに合わせて選んだもの（`salon.json` の `coupons`）、スタイリスト名・投稿者、文章。
   - 「結果不明」になった投稿は、ツールが2分・5分・15分後に投稿一覧（スタイルは1ページ目と最後のページ、ブログは1ページ目）で自動で照合します。見つかれば投稿済み、3回とも見つからなければ「登録なし」として失敗（FAILED）にし、二重投稿を避けるため自動では送り直しません（送り直すときは `retry`）。人が確かめる必要はありませんが、自分で確かめたときは、`npm.cmd run reconcile -- --id job_id --registered --basis "一覧で確認"`（登録されていなければ `--not-registered`）を実行します。自動で登録し直すことはありません。
5. ほかの投稿先も同じように、1件ずつ行います（`--route style.ladies`・`--route blog.mens`・`--route blog.ladies`）。

### 15. 通常運転を始める

使う投稿先すべての初回の投稿が済んだら、`npm.cmd run resume` を実行します。以後は投稿ごとの承認は不要で、投稿枠の時刻に1件ずつ投稿します。画面設定を変えた投稿先は、もう一度その投稿先の初回の1件（14）から行います。

### 開発担当と画面を合わせる日の流れ（画面の調査が済んでいない場合）

まだ実際の画面での確認が済んでいない（開発は模擬の画面で行いました）ため、最初の本番投稿の前に、開発担当と日時を決めて次の順に進めます。

1. 1〜3（自動操作の可否・件数・ログイン条件の記録）
2. 4〜7（接続先、拡張機能の読み込み、接続、ログイン、投稿先URL）
3. 8（4つの投稿画面と、完了・一覧の画面の調査）→ 承認したファイル名を開発担当へ
4. 9（開発担当が画面設定を作り、オーナーが質問に答える）→ 10・11（画像の添付と画面の確認）→ 12（確認済みの記録）
5. 13（dry-run）→ 14（オーナーの承認のもと、投稿先ごとに1件だけ本番投稿し、画面で確認）→ 15（通常運転）

### 困ったとき（本番）

1. `npm.cmd run status` で「送信を止めている理由」と「対処」、「SALON BOARD への投稿」の欄（配布の状態・拡張機能・ログイン・対応が必要な作業）を見ます。拡張機能のポップアップにも同じ内容が出ます。
2. ログイン・画像・設定など、原因を直します。
3. 結果不明の投稿があれば、先に `npm.cmd run reconcile` で照合します（SALON BOARD の投稿一覧で確かめた結果を記録します）。
4. 必要な job を `npm.cmd run retry` で再開します。
5. `npm.cmd run resume` で再開します。画面の確認が必要な停止（ログイン切れ・店舗違い・画面の変化など）は、ツールが画面を確かめて（入力も登録もしません）から解除します。二重登録の疑いで止まったときは、画面で確かめてから `npm.cmd run resume -- --confirm-checked` を実行します。

### 本番投稿のコマンド

| コマンド | 内容 | 終了コード |
|---|---|---|
| `npm.cmd run live:single -- --route style.mens` | 投稿先ごとの初回の本番投稿を1件だけ行います。`--route` の値は style.mens・style.ladies・blog.mens・blog.ladies のどれかです。`--yes` なしで内容を表示し、同じコマンドに `--yes` を付けると表示した job を予定します。`--job job_id` を足すと job を選べます（省くと一番古い投稿待ち） | 0 表示した／予定した、1 断られた（理由を表示）・書き方の誤り、2 ツールが起動していない・応答を確認できない |
| `npm.cmd run preflight -- --route style.mens` | 投稿画面を開いて確かめるだけ（入力・添付・登録はしません）。`--route` の値は live:single と同じで、`--route configured` なら設定済みの投稿先すべてです。最大90秒待って結果を表示します | 0 問題なし、1 問題あり・断られた・書き方の誤り、2 結果が来ない（Chrome と投稿用のウィンドウを確認）・ツールが起動していない |
| `npm.cmd run pair` | 拡張機能と接続し直すための接続コードを表示します | 0 表示した、2 ツールが起動していない |
| `npm.cmd run probe -- --arm --yes` | 画像添付の確認を10分間だけ受け付けます（登録しません） | 0 受け付けた、1 断られた、2 ツールが起動していない |
| `npm.cmd run survey:list`／`npm.cmd run survey:show -- --file ファイル名` | 画面の調査結果の一覧・中身の表示と承認（承認は `--approve` を足します） | 0 正常、1 書き方の誤り |
| `npm.cmd run checks:record -- show` | 本番投稿の前提の記録（オーナーだけが実行します。`show` で一覧と、項目ごとの記録のコマンドを表示します） | 0 記録した、1 書き方や内容の誤り |
| `npm.cmd run pause`／`resume`／`retry`／`reconcile` | 一時停止・再開・失敗した job の再開・結果不明の照合（ツールの動作中は動作中のツールに頼みます） | 0 正常、1 断られた・停止が残っている、2 応答を確認できない |
| `npm.cmd run redraft` | まだ投稿に回していない投稿待ちの文章を、いまの文章の設定で書き直します（画像の解析はそのまま使います。1件につき文章の作成と検査の AI を1回ずつ使います）。`-- --type style`（または `blog`）でその種類だけ、`-- --id job_id` で1件だけ、`-- --dry` で対象の一覧だけを表示します（何も変えません）。動作中は動作中のツールが裏で書き直し、止まっていれば次の起動で書き直します | 0 正常、1 断られた（理由を表示）・書き方の誤り、2 応答を確認できない |

`<投稿先>` は `style.mens`（スタイル・メンズ）・`style.ladies`（スタイル・レディース）・`blog.mens`（ブログ・メンズ）・`blog.ladies`（ブログ・レディース）です。`npm.cmd run` の後ろの `--` は省かないでください。

### 投稿できる時間帯と、開いたままにしておくもの

- **投稿できる時間帯**は `config\schedule.json` の `post_start`〜`post_end`（初期値 10:00〜21:00）のうち、営業時間（作業指示書で変えた場合はその時間）と重なる時間です。この中の投稿枠の時刻に1件ずつ送信します。終わりの3分前を過ぎると新しい投稿を始めず、次の枠（翌日など）に回します。
- 投稿するには、その時間帯に**ツール（黒い画面）、Chrome、インターネット接続、Windows へのログイン**がそのまま動いている必要があります。ツールが動いている間はパソコンが自動でスリープに入りませんが、自分でスリープにしたとき・ふたを閉じたとき・電源が切れている間は投稿できません。

### 安全のための設定

- **フォルダのアクセス権**：`status` やツールの画面に「このフォルダは、このPCの他のユーザーも書き換えられる設定になっています」と出たときは、このパソコンのほかの Windows ユーザーが設定や `.env` を書き換えられる状態です。このパソコンを1人だけで使っているなら、そのままでも動きます。直すときは、次のどちらかを行ってください（ツールが自動で変えることはありません）。
  1. **（おすすめ）** ツールを止めてから、プロジェクトのフォルダごと `C:\Users\<あなたの名前>\` の下（例：`C:\Users\<名前>\Documents\`）へ移し、移した先で起動し直します。
  2. 開発担当に確認したうえで、フォルダの場所に置き換えて次のコマンドを PowerShell で実行します（あなた・SYSTEM・Administrators だけが使えるようにします）。

     ```powershell
     icacls "C:\SalonTool" /inheritance:r /grant:r "${env:USERNAME}:(OI)(CI)F" "*S-1-5-18:(OI)(CI)F" "*S-1-5-32-544:(OI)(CI)F" /t /c
     ```

- **接続の作り直し**：拡張機能との接続だけを作り直すときは、ツールの動作中に別の PowerShell で `npm.cmd run pair` を実行し、表示されたコードをポップアップの「接続コード」の欄に入力して「送信」を押します（前の接続は使えなくなります）。接続のための秘密の値ごと作り直すときは、ツールを止め、`.env` をメモ帳で開いて `LOCAL_API_TOKEN=` の行の `=` より後ろを消して保存し、`起動.bat`（または `npm.cmd start`）で起動します（新しい値が自動で書き込まれ、前の接続は使えなくなり、接続コードが表示されます）。ポップアップの「接続」を押し、「接続コード」の欄にそのコードを入力して「送信」を押し、確認記号が同じことを確かめます。
- **Chrome がツールへ接続できないとき**：ポップアップに「ツール（127.0.0.1）へ接続できません」と出たら、次を確かめます。(1) ツール（黒い画面）が動いているか。(2) Chrome の「設定」→「プライバシーとセキュリティ」→「サイトの設定」で、ローカル ネットワークへのアクセスが止められていないか。(3) セキュリティソフトが、このパソコンの中の接続（127.0.0.1 の 3001 番。2つ目のツールは `server.port` の番号）を止めていないか。(4) ツールの起動時に `PORT_IN_USE` と出ていないか（ほかのソフトが3001番を使っています）。
- **セキュリティの更新（開発担当が行います）**：`npm.cmd audit` で問題を確かめ、`package.json` で版を固定している部品（esbuild・jsdom・@types/chrome など）を更新して `npm.cmd install` し、`npm.cmd run typecheck`・`lint`・`test`・`test:e2e`・`build`・`build:extension` をすべてやり直します。更新後は拡張機能を `build:extension` で作り直し、`chrome://extensions` で再読み込みします。

## AI の設定

初期設定では、写真の解析と文章づくりに Google の AI「Gemini」の**無料枠**を使います（`config\settings.json` の `ai.provider` が `"gemini"`）。dry-run（テスト運転）では AI を呼ばずに仮の文章を使うので、キーが無くても動きます（`ai.dry_run_use_real_ai` を `true` にすると dry-run でも本物の AI を使います）。

> OpenAI（ChatGPT）の API は、確認した主なモデルでは無料枠がなかったため（2026年10月時点）、無料で使える Gemini にしています。

### 1. 無料の API キーを作る

1. ブラウザで Google AI Studio（https://aistudio.google.com/）を開き、Google アカウントでログインします。
2. API キーの画面でキーを作ります。**無料枠ではクレジットカードの登録は要りません。** 支払い方法（請求先）を登録すると有料の扱いに変わるので、無料で使う間は登録しないでください。
3. 作ったキーをコピーします。キーはパスワードと同じです。人に見せたり、メールやチャットに貼ったりしないでください。AI Studio で作ったキーを使ってください（Google Cloud で以前に作った制限なしのキーは使えないことがあります）。
4. **支払い方法を登録済みの Google Cloud のプロジェクトでキーを作ると、無料枠ではなく有料の扱いになります。** AI Studio の上限の画面（https://aistudio.google.com/rate-limit）で、キーのプロジェクトが無料（Free）の扱いになっていることを確かめてください。このツールは料金の扱いを Google に問い合わせないため、有料の扱いのまま `ai.gemini.free_tier` が `true` だと、利用額を0ドルと記録し、予算（`ai.budget`）では止まりません。

### 2. キーを `.env` に書く

- このフォルダの `.env.example` をコピーして `.env` という名前にし（`.env` は最初の起動で自動で作られます。すでにあるときは上書きせず、そのまま開きます。上書きすると拡張機能の接続をやり直すことになります）、メモ帳で開いて `GEMINI_API_KEY=` の後ろにキーを貼り付けて保存します（例：`GEMINI_API_KEY=AIza…`）。
- キーは画面やログには表示しません（`status` には末尾4文字だけ出します）。キーが無いまま本番で起動すると「AIのAPIキーが見つかりません」（`AI_AUTH_ERROR`）、キーが正しくないときも `AI_AUTH_ERROR` と表示されます。

### 3. 無料枠の上限（1日に作れる投稿の数）

- 無料枠には「1分あたり」と「1日あたり」の回数の上限があり、モデルごとに決まっています。1日の回数は米国太平洋時間の0時に数え直されます。日本時間では**16:00**（米国の夏時間の間）か **17:00**（米国の冬時間の間。11月の第1日曜の翌日から3月の第2日曜まで）です。次に数え直す時刻は、本物のAIを使う設定のとき `npm.cmd run status` でも確かめられます。
- **初期設定の上限の回数は仮の値です**（`gemini-3.8-flash`・`gemini-3.6-flash`・`gemini-3.5-flash` は1分5回・1日100回、`gemini-3.5-flash-lite` は1分10回・1日200回）。Google は無料枠の正確な回数を、AI Studio にログインして見られる上限の画面（https://aistudio.google.com/rate-limit）でだけ公開しています。実際の値を確かめて、`settings.json` の `ai.gemini.limits` のモデルごとの `rpm`（1分の回数）と `rpd`（1日の回数）を直し、`verified_at` に確認した日（例：`"2026-10-06"`）を書いてください。確かめるまでは、本物のAIを使う設定のとき `status` にも「仮の値です」と出ます（dry-run の模擬（mock）の AI では出ません）。
- 1件の投稿で AI を3〜5回使います（写真の解析1回・文章づくり1〜3回（作り直しを含む）・最後の確認1回）。解析と文章づくりは `gemini-3.8-flash`、最後の確認は `gemini-3.5-flash-lite` を使うので、**1日に作れる投稿の数は、おおよそ「`gemini-3.8-flash` の1日の回数 ÷ 2〜4」**です（仮の値の1日100回なら20〜45件ほど。作り直しが多いと減ります）。
- このツールは上限を超えないよう、自分で回数を数えて呼び出しの間隔をあけます（1分の上限に近いときは少し待ってから呼びます）。安全のため、1日の回数の20回につき1回分は使わずに残します（1日100回なら95回で止めます）。
- 1日の上限に達すると、そのモデルを使う AI の処理を止め、「Geminiの無料枠の1日の上限に達したため、日本時間 16:00 以降に再開します」のように表示します。数え直しの時刻を過ぎると、また AI を使えるようになります。
- Google から「上限に達した」と返ってきたときは、1日の上限だと分かればそのモデルを数え直しの時刻まで止め、どの上限か分からなければ1分・2分・4分…と間を広げて休ませます。Google から応答が無い状態（混雑・接続の不調など）が続いたときも、同じように間を広げて休ませます。どちらの場合も呼び出しを続けることはなく、無料の回数を無駄に使いません。設定の回数が実際より多くても、こうして止まるか休むので、使い過ぎにはなりません。
- **予備のモデル**：使うモデルが混み合っていて答えられないとき（Google の「high demand」、HTTP 503）や、そのモデルが1日の上限に達したときは、同じ依頼を `settings.json` の `ai.gemini.fallback_models` のモデルで順に試します（初期設定では、解析と文章づくりは `gemini-3.6-flash` → `gemini-3.5-flash`、最後の確認は `gemini-3.5-flash`）。混み合ったモデルだけを少しの間（1分から）休ませ、その間はほかのモデルをふだんどおり使います。予備のモデルも回数をモデルごとに数えるので、`ai.gemini.limits` に上限が要ります。予備を使わない段階は `[]` にします。
- 止まった後に設定を直したとき：
  - このツールが自分で数えた上限で止まっているときは、`rpd` を直す（または下の5のとおり有料に切り替える）と、再起動しなくても次の呼び出しから再開します。
  - Google からの知らせで止まっている・休んでいるときは、`rpd` を直しても数え直しの時刻（休みならその終わり）までそのままです。有料に切り替えたとき（`free_tier` を `false` にしたとき）は、無料枠で記録した停止は効かなくなります。
- 回数の記録は `data\ai-usage\request-quota.json` にあり、ツールを起動し直しても引き継ぎます（消さないでください）。

### 4. 写真のデータとお客様の同意（必ずお読みください）

- 写真（縮小し、撮影日時や位置などの情報を消したもの）と文章の送り先は、Google の Gemini API（`generativelanguage.googleapis.com`）だけです（`.env` でほかのサービスを選んだ段階は、そのサービスに送られます。下の6）。
- **無料枠では、送った写真と文章を Google が自社のサービスや AI の改善に使い、Google の担当者が内容を読むことがあります**（Gemini API の利用規約の「無料のサービス」の項。読まれる前に、アカウントやキーとの結び付きは外されます）。同じ規約は、無料のサービスに**機密の情報や個人の情報を送らないこと**を求めています。また、利用者は18歳以上で、仕事のための利用が前提です。
- **保存について**：送った写真と文章を Google がどのくらいの期間保存するかは、Gemini API の利用規約（https://ai.google.dev/gemini-api/terms）に従います。このツールの呼び出し方（generateContent）には保存の期間を選ぶ設定が無く、Google 側に会話を保存させる機能（Interactions API の保存）も使っていません。無料枠では、上のとおり改善のためにも使われます。
- お客様の施術写真を使う前に、必ずお客様の同意を得てください。
- 有料の扱いでは、送った内容は Google の改善に使われません。あとから設定の変更だけで切り替えられます（下の5）。
- 同意のお願いの文の例（店内の掲示や同意書に）：
  > 施術写真は、サロンの投稿（ヘアスタイル・ブログ）の文章を作るため、外部のAIサービス（Google）で解析します。無料版のため、写真はGoogleのサービス改善に使われ、Googleの担当者が確認する場合があります。

### 5. あとから有料にする・Claude に切り替える（設定の変更だけでできます）

- **Gemini を有料で使う**：Google AI Studio で支払い方法を登録し（最初に5ドル以上の前払いが必要です）、`settings.json` の `ai.gemini.free_tier` を `false` にして、使うモデル（予備のモデル `ai.gemini.fallback_models` を含みます）の料金（100万トークンあたりのドル）を `ai.gemini.pricing` に書きます（書かないと利用額を見積もれないため、AI を呼びません）。有料では、送った内容は Google の改善に使われません。利用額は `ai.budget`（1日・1か月の予算）に達すると止まります。回数の上限は有料の値に合わせて `ai.gemini.limits` を直すか、そのモデルの行を消してください。
- **Claude（Anthropic）に切り替える**：`ai.provider` を `"anthropic"` にし、Claude Console（https://console.anthropic.com/）で作ったキーを `.env` の `ANTHROPIC_API_KEY=` の後ろに書きます。モデルと料金は `ai.anthropic` にあります。料金がかかり、`ai.budget` の予算に達すると止まります。
- **ChatGPT（OpenAI）に切り替える**：下の「ChatGPT（OpenAI）を使う」のとおりです（`.env` はキーの1行だけ）。
- `.env` だけで段階ごとにサービスやモデルを変えることもできます（下の6）。
- 設定を変えたら、ツールを起動し直してください。特に `ai.provider`（Gemini・Claude・OpenAI の切り替え）は、起動し直すまで反映されません（起動したまま変えると、起動し直すまで AI を止めて、その旨を表示します）。

#### ChatGPT（OpenAI）を使う（`.env` は `OPENAI_API_KEY` の1行だけ）

1. 開発担当が `config\settings.json` の `ai.provider` を `"openai"` にします。**このバージョンのツールに更新して起動し直してから**書いてください（前のバージョンのツールは `"openai"` を設定の誤りとして止まります）。
2. `.env` に OpenAI の管理画面（https://platform.openai.com/api-keys）で作ったキーを1行だけ書きます：`OPENAI_API_KEY=sk-…`（支払い方法の登録が必要です）。`AI_<段階>_` の行や料金の行は要りません。
3. ツールを止めて `npm.cmd run ai:test` で3つの段階が「OK」になるのを確かめ、起動し直します。

用途ごとに次のモデルを使います（料金は2026年10月9日に OpenAI のモデルと料金の説明で確かめた値。100万トークンあたりのドル）：

| 用途 | モデル | 推論の強さ（reasoning effort） | 入力 / キャッシュ入力 / 出力 |
|---|---|---|---|
| 画像の解析 | `gpt-6.1-sol` | 中（`medium`） | 2 / 0.10 / 10 |
| 文章づくり | `gpt-6-luna` | 中（`medium`） | 0.10 / 0.01 / 0.50 |
| 最後の確認 | `gpt-6.1-sol` | 中（`medium`） | 2 / 0.10 / 10 |
| トレンドのWeb検索（毎週日曜、メンズ・レディース） | `gpt-6-astra` | 高（`high`） | 10 / 1.00 / 50 ＋ 検索1回 0.01（1,000回で10ドル） |

- **料金**：Web検索は、検索の回数（1,000回で10ドル）に加えて、検索で読んだ内容もトークンとして `gpt-6-astra` の料金で数えます。毎週日曜に、メンズ・レディースで各1回調べます。どの呼び出しも、答えに出た検索の回数（無ければ1回）と使ったトークンから利用額を見積もり、`ai.budget`（1日・1か月の予算）に達すると止まります。Web検索は時間がかかるため、`ai.timeout_seconds` が300秒より短くても300秒まで待ち、出力の上限は32768トークン以上にします（ほかの呼び出しは今までどおり）。
- **変えるとき**：`settings.json` の `ai` の中に `openai` の項目を書きます（書かなければ下の初期値）。保存すれば、起動し直さなくても次の呼び出しから使います。推論の強さは `none`・`minimal`・`low`・`medium`・`high`・`xhigh`・`max` で、モデルが受け付けない値は設定の誤りとして止まります（`none` を使えるのは `gpt-6-luna` だけ。`gpt-6-astra`・`gpt-6.1-sol` は `low` 以上）。新しいモデルにするときは `pricing` にその料金も足してください（無いモデルは、表のいちばん高い料金の2倍で見積もります）。

```
"openai": {
  "models": { "analysis": "gpt-6.1-sol", "generation": "gpt-6-luna", "check": "gpt-6.1-sol" },
  "web_search_model": "gpt-6-astra",
  "reasoning_effort": { "analysis": "medium", "generation": "medium", "check": "medium", "web_search": "high" },
  "pricing": {
    "gpt-6-astra": { "input_per_mtok": 10, "output_per_mtok": 50, "cache_read_per_mtok": 1, "verified_at": "2026-10-09" },
    "gpt-6.1-sol": { "input_per_mtok": 2, "output_per_mtok": 10, "cache_read_per_mtok": 0.1, "verified_at": "2026-10-09" },
    "gpt-6-luna": { "input_per_mtok": 0.1, "output_per_mtok": 0.5, "cache_read_per_mtok": 0.01, "verified_at": "2026-10-09" }
  },
  "web_search_call_usd": 0.01
}
```

- `.env` の `AI_<段階>_*` は、OpenAI を選んだときも今までどおりその段階だけ上書きします（例：`AI_GENERATION_MODEL=gpt-6.1-sol`）。推論の強さは、その段階が `ai.openai.models` のモデルを使うときだけ送ります（`.env` で別のモデルにした段階には送らず、モデルの標準のままです）。`.env` で文章生成だけを OpenAI にしたときも、Web検索は `ai.openai.web_search_model` を使います。
- 写真（縮小・情報削除済み）と文章の材料は OpenAI（`api.openai.com`）に送られます。Web検索の依頼は OpenAI 側に保存しない指定（`store: false`）で送ります。データの扱いは OpenAI の利用規約で確かめ、お客様の同意を得てください。Gemini の無料枠の回数の表示（`status` の「無料枠」「仮の値」）は、OpenAI の段階には出ません。

### 6. 段階ごとにサービス・モデルを変える（.env）

写真の解析・文章づくり・最後の確認のそれぞれで、使う AI のサービス・モデル・キーを **`.env` ファイルだけで** 変えられます。`.env` に書いた値は `settings.json` の `ai.*` より優先されます。何も書かなければ、上の1〜5のとおり `settings.json` の設定で動きます（`GEMINI_API_KEY=` などの従来のキーもそのまま使えます）。

#### 書く項目

`<段階>` には `ANALYSIS`（画像解析）・`GENERATION`（文章生成）・`CHECK`（整合性チェック。最後の確認）のどれかが入ります。

| 項目 | 書く値 |
|---|---|
| `AI_<段階>_PROVIDER` | `gemini` ・ `claude`（`anthropic` でも可）・ `openai` ・ `openai_compatible`（OpenAI 互換のサービスやパソコン内の AI） |
| `AI_<段階>_MODEL` | モデル名（例：`gemini-3.8-flash`、`claude-opus-5-5`、`gpt-6.1-sol`） |
| `AI_<段階>_API_KEY` | そのサービスのキー（書かなければ `GEMINI_API_KEY`・`ANTHROPIC_API_KEY`・`OPENAI_API_KEY` を使います） |
| `AI_<段階>_BASE_URL` | 接続先の URL。`openai_compatible` では必ず書きます。`https://` で始まる URL だけ使えます（パソコン内の AI だけ `http://localhost` か `http://127.0.0.1` も可） |
| `AI_<段階>_FREE_TIER` | Gemini の無料枠なら `true`、有料なら `false`（Gemini を使う段階はすべて同じにします） |
| `AI_<段階>_FALLBACK_MODELS` | Gemini の予備のモデル（カンマ区切り。例：`gemini-3.6-flash,gemini-3.5-flash`）。混み合って答えられないときや1日の上限のとき、同じ依頼を順に試します（上の3）。書かなければ `settings.json` の `ai.gemini.fallback_models` を使います。無料枠で `ai.gemini.limits` に無いモデルは、仮の上限（1分5回・1日100回）で数えます |
| `AI_<段階>_API_VERSION` | Gemini の API のバージョン名（例：`v1beta`）。書かなければ `settings.json` の `ai.gemini.api_version`（初期値 `null` = ツールが使っている SDK の標準）。Google がバージョンを終了したときに使います（下の「AIのAPIやモデルが変わったとき」）。`status` の「AIの設定」には、決めているときだけ「APIバージョン …」と出ます |
| `AI_<段階>_MAX_TOKENS` | AI が1回に返せる長さ（出力トークン）の下限。考えるタイプのモデルで答えが途中で切れるときに、大きめの整数（例：`16000`）を書きます。OpenAI・OpenAI 互換・Claude では、ツールが決めた長さがこの数より小さいときだけこの数に引き上げます（OpenAI は標準の下限 16384 の代わりにこの数を使います。OpenAI のWeb検索の下限 32768 は、これより大きい数のときだけこの数にします）。Gemini では `ai.gemini.max_output_tokens` のその段階の値をこの数に置き換えます（上限 65536） |
| `AI_<段階>_JSON_MODE` | `openai`・`openai_compatible` の答えの形式。`json_schema`（既定）で動かないサービスは `json_object`、それでもだめなら `none` |
| `AI_<段階>_PRICE_IN` / `AI_<段階>_PRICE_OUT` | 有料のときの料金（入力・出力それぞれ100万トークンあたりのドル）。利用額の見積もりと予算（`ai.budget`）に使います。有料のサービス（OpenAI、インターネット上の `openai_compatible`、有料の Gemini、Claude）で料金が分からないモデルは、書かないと AI を使いません（予算で止められないため。Gemini・Claude・OpenAI は `settings.json` の料金表（OpenAI は `ai.openai.pricing`）にあるモデルなら不要です）。無料で使える接続先なら両方 `0` と書きます。パソコン内の AI（`http://localhost` など）は書かなくても使えます |

- **`CHECK` は、書かなかった項目を `GENERATION` から引き継ぎます。** 文章づくりと同じでよければ `CHECK` の行は要りません（別のサービスを書いたときは引き継ぎません）。
- 書き方：1行に「名前=値」。`#` から後ろはメモです。値を `"…"` で囲ってもかまいません。全角の文字はメモにだけ使ってください。
- **変えたら保存して、ツールを起動し直してください**（起動したままでは反映されません）。`npm.cmd run status` の「AIの設定」で、段階ごとのサービス・モデル・キー（末尾4文字だけ）・無料枠・接続先を確かめられます。
- 書き間違いがあると、起動のときに「`.env 12行目（AI_ANALYSIS_PROVIDER）: …`」のように行番号と直し方を表示して止まります（`CONFIG_INVALID`、終了コード 1）。dry-run で AI を呼ばない設定のときは、ログに注意として残すだけです。知らない `AI_` の項目は注意として表示します（書き間違いの候補も出します）。
- 縮小した写真（各投稿の `ai.jpg`）は、画像解析・文章生成・整合性チェックの3つの段階すべてのサービスに送られます（解析だけではありません）。文章は `GENERATION`・`CHECK` のサービスに送られます。Gemini の無料枠の扱いは上の4のとおりです。ほかのサービスを選んだときは、そのサービスの利用規約でデータの扱いを確かめてください。お客様の同意が必要なのはどのサービスでも同じです。

#### 試す（`npm.cmd run ai:test`）

ツールを止めた状態で `npm.cmd run ai:test` を実行すると、使う段階ごとに小さな依頼を1回ずつ送り、「OK」か、失敗の理由と直し方（キーの誤り・モデル名の誤り・回数や予算の上限・混み合っている・接続できない など）を表示します。Gemini の予備のモデルが答えたときは「OK（Google Gemini / モデル gemini-3.6-flash ※混雑などのため予備のモデルで応答）」のように、答えたモデルを表示します。本番と同じく、どの段階にもこのツールが作る 64×64 の単色の画像を付けて送り、段階ごとに「画像も読めました」と表示します（失敗した段階には、画像を受け付けたか確かめられなかったことを表示します。お客様の写真は使いません）。投稿や job には何もしません。送った回数と利用額は、ふだんの呼び出しと同じように数えます（無料枠の回数を1〜3回使います）。

#### ひな形（コピーして `.env` に貼り、キーを書き換えます）

**Gemini の無料枠ですべて**（初期設定と同じ）：

```
AI_ANALYSIS_PROVIDER=gemini
AI_ANALYSIS_MODEL=gemini-3.8-flash
AI_ANALYSIS_API_KEY=ここにGeminiのキー
AI_ANALYSIS_FREE_TIER=true
AI_GENERATION_PROVIDER=gemini
AI_GENERATION_MODEL=gemini-3.8-flash
AI_GENERATION_API_KEY=ここにGeminiのキー
AI_GENERATION_FREE_TIER=true
AI_CHECK_MODEL=gemini-3.5-flash-lite
```

#### キーの入手先

- Gemini：Google AI Studio（https://aistudio.google.com/）。無料枠ではクレジットカードの登録は要りません（上の1）。
- Claude：Claude Console（https://console.anthropic.com/）。
- OpenAI：OpenAI の管理画面（https://platform.openai.com/api-keys）。支払い方法の登録が必要です。
- OpenAI 互換のサービス：そのサービスの管理画面。

#### 新しいモデルが出たとき

1. `.env` の `AI_<段階>_MODEL=` を新しいモデル名に書き換えて保存します（有料なら `PRICE_IN`・`PRICE_OUT` も新しい料金に）。
2. ツールを止めて `npm.cmd run ai:test` で確かめます。
3. ツールを起動し直します。

Gemini の無料枠で `settings.json` の `ai.gemini.limits` に無いモデルを選んだときは、仮の上限（1分5回・1日100回）で数えます。AI Studio の上限の画面で実際の回数を確かめて、`ai.gemini.limits` にそのモデルの行を足してください。

#### AIのAPIやモデルが変わったとき

Google などがモデルや API を変えても、ツールはできるだけ自分で動き続けます。直せないときは、無料枠の回数を使い切る前に止まって、日本語で理由と直し方を表示します。

**ツールが自分でやること**

- モデルが無くなった・その依頼を受け付けない・答えが読めない形だったとき、Gemini では `ai.gemini.fallback_models`（`.env` の `AI_<段階>_FALLBACK_MODELS`）の予備のモデルに順に移ります。
- 受け付けられなかった依頼は、もっと簡単な形にして送り直します。
- 答えの形が少し違っても、読み取れる範囲は寛容に読みます。
- 同じ失敗が3回続いたら、それ以上は送らず、理由を表示して止まります（直らない依頼で無料枠の回数を使い切らないためです）。

**オーナーがやること**

1. ツールを止めて `npm.cmd run ai:test` を実行し、段階ごとに「OK」か失敗の理由を確かめます。
2. モデルが変わったとき：`settings.json` の `ai.gemini.models` と `ai.gemini.fallback_models` を書き換えます（保存すれば、再起動しなくても反映されます。`.env` に `AI_<段階>_MODEL` や `AI_<段階>_FALLBACK_MODELS` を書いている段階は、`.env` が優先なので `.env` を直して起動し直します）。無料枠の新しいモデルは、`ai.gemini.limits` にもそのモデルの行を足します（無いと仮の上限で数えます）。
3. Google の API のバージョンが終了したとき：`.env` に `AI_<段階>_API_VERSION=`（新しいバージョン名）を書くか、`settings.json` の `ai.gemini.api_version` に書いて、起動し直します。
4. 答えが途中で切れるとき：`AI_<段階>_MAX_TOKENS=`（大きめの整数）を書きます。
5. Gemini が使えないままのとき：その段階を別のサービスに切り替えます（`.env` を直して起動し直します）。
   - OpenAI：5の「ChatGPT（OpenAI）を使う」（すべて）か、6のひな形「OpenAI」（段階ごと。`PROVIDER=openai`、`API_KEY`。料金表に無いモデルなら `MODEL` と `PRICE_IN`・`PRICE_OUT`）。
   - Google の OpenAI 互換の Gemini：`AI_<段階>_PROVIDER=openai_compatible`、`AI_<段階>_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/`、`AI_<段階>_MODEL=`（モデル名）、`AI_<段階>_API_KEY=`（Gemini のキー）、`AI_<段階>_PRICE_IN=0`、`AI_<段階>_PRICE_OUT=0`。うまく動かないときは `AI_<段階>_JSON_MODE=json_object`（だめなら `none`）を試します。**この方法では、無料枠の回数の管理や予備のモデルへの切り替えは Gemini として使うときより弱くなります**（`FREE_TIER`・`FALLBACK_MODELS` は使えません）。回数の上限に気をつけてください。

### 7. Claude の API キーを用意する（settings.json で Claude を使うとき）

`settings.json` の `ai.provider` を `"anthropic"` にして Anthropic 社の AI「Claude」を使う場合の手順です（モデルは `ai.anthropic.models`。初期値は3つとも `claude-opus-5-5`）。`.env` で段階ごとに Claude を選ぶときは、6のひな形「Claude ですべて」を使います。

1. Anthropic Console（https://console.anthropic.com/ ）にログインし、支払いの設定（クレジットの購入）をします。Console の「Limits」で月の利用上限も決めておくと、このツールの予算とあわせて二重の歯止めになります。
2. Console の「API Keys」で「Create Key」を押し、キーを作ります。表示されたキー（`sk-ant-` で始まる文字列）をコピーします（あとから見直せないので、すぐに次の手順へ）。
3. このツールのフォルダ（`package.json` があるフォルダ）の `.env.example` をコピーして名前を `.env` にし（すでに `.env` があるときは上書きせず、それを開きます）、メモ帳で開いて次のように書いて保存します。

   ```text
   ANTHROPIC_API_KEY=sk-ant-ここにコピーしたキー
   ```

4. `config\settings.json` の `ai.provider` を `"anthropic"` にします。dry-run でも本物の AI を使いたいときは、`ai.dry_run_use_real_ai` を `true` にします（`false` の間は dry-run では模擬の AI を使います）。
5. ツールを起動し直します。`npm.cmd run status` の「AI」に「APIキー: 設定あり（…値は表示しません）」と出れば準備できています。

- **API キーは誰にも教えないでください。** メール・チャット・画面の写真にも載せないでください。このツールはキーを画面やログに表示しません（`status` の「AIの設定」には末尾4文字だけ出します）。漏れたかもしれないときは、Console でそのキーを削除（Delete）し、新しいキーを作って `.env` を書き換えてください。
- キーが間違っている・使えなくなったときは、すべての写真の準備を止め、`status` に「AI_AUTH_ERROR」と理由を表示します。`.env` を直して起動し直すと再開します。
- `.env` に書いた値より、パソコンの環境変数に同じ名前の値があればそちらを使います（空の環境変数は無視します）。

### 8. 費用の上限（予算）

AI を1回使うごとに、使った量（トークン数）と見積額を `data\ai-usage\YYYY-MM.json` に記録します（dry-run と本番で共通。消さないでください）。Gemini の無料枠では見積額は0ドルで、回数の上限（`ai.daily_request_limit` と Gemini の1日の上限）で止まります。写真1枚につき、解析・文章の作成・最後の確認の3回（作り直したときはその分も）使います。

| 設定（`settings.json`） | 初期値 | 意味 |
|---|---|---|
| `ai.budget.daily_usd` | 3 | 1日（日本時間）の見積額の上限（米ドル） |
| `ai.budget.monthly_usd` | 60 | 1か月の見積額の上限（米ドル） |
| `ai.daily_request_limit` | 200 | 1日に AI を呼ぶ回数の上限 |
| `ai.max_regenerations` | 2 | 検査に通らなかったときに作り直す回数の上限 |

- どれかの上限に達すると、**すべての写真の準備を止めて AI を呼びません**（画像の取込は続けます）。`status` に「【停止中】AIの処理を止めています」と理由が出ます。翌日（日本時間0時）・翌月になるか、上限の値を増やして保存すると、自動で再開します（再起動は不要です）。
- 見積額は、使っている AI の料金表（Claude は `ai.anthropic.pricing`、有料の Gemini は `ai.gemini.pricing`。`.env` に `AI_<段階>_PRICE_IN`・`PRICE_OUT` を書いた段階はその値）の単価（100万トークンあたりの米ドル）で計算します。どのサービスでも、時間切れや接続切れの呼出しは、実際には使われていなくても出力の上限まで使ったものとして多めに数えます。料金表に無いモデルは、料金表で最も高い単価の2倍で数えます。
- 料金表には `claude-opus-5-5`（入力4・出力20・キャッシュ読込0.2、2026-10-04 確認）のほか、AI が安全上の理由で答えなかったときに代わりに答えるモデル `claude-opus-5`・`claude-opus-4-8`（入力5・出力25・キャッシュ読込0.5）を入れています。**後の2つの単価はまだ確認していない仮の値です。** Anthropic の料金ページ（https://www.anthropic.com/pricing ）で確かめて、違っていれば値と `verified_at`（確認した日）を直してください。
- 実際の請求額は Anthropic Console（有料の Gemini なら Google AI Studio）で確認してください。このツールの見積額は目安です。
- AI のサービスから残高（クレジット）が足りないと返ってきたときは、すべての写真の準備を止めます。支払いの設定を確認してから、ツールを起動し直してください。

### 9. 写真とデータの扱い

- AI に送るのは、元の写真を縮小（長い辺1568ピクセル）し、撮影日時や位置情報などの情報（EXIF）を消した JPEG のコピー（各投稿のフォルダの `ai.jpg`）だけです。元の写真は送らず、変更もしません。
- 写真のほかに、文章の材料（画像解析の結果、`config` の語や方針、Excel の参考例、トレンド語、作業指示書の内容、写真の補足ファイルのメモ）を送ります。これらは「参考データ」として渡し、AI への命令としては扱いません。
- 送り先は使っている AI だけです。**初期設定の Gemini の無料枠では、送った内容が Google のサービスの改善に使われ、担当者が読むことがあります**（上の4を必ずお読みください）。
- Claude を使う場合：Anthropic は、API で送られた内容を初期設定では AI の学習に使わないとしています（利用規約やプライバシーの方針は変わることがあるため、Anthropic のサイトで最新の内容を確認してください）。
- お客様の写真を AI で解析して投稿に使うことについて、**お客様の同意をいただくことをおすすめします。** Gemini の無料枠での文面の例は、上の4にあります。Claude を使う場合は、例えば次のような文面を、撮影の前にお見せしたり、店内に掲示したりする方法があります。

  > 撮影したヘアスタイルの写真は、当店のホットペッパービューティー（SALON BOARD）への掲載と、その紹介文づくりに使わせていただくことがあります。紹介文づくりのため、写真を縮小・撮影情報を削除したうえで AI サービス（Anthropic 社の Claude）で解析します。掲載を希望されない場合や、お顔が写る写真の使用を控えたい場合は、お気軽にスタッフへお申し付けください。

- 模擬の AI（dry-run の初期設定）は、写真も文章も外部へ送りません。
- スタイル投稿の「モデル情報」（髪量・髪質・太さ・クセ・顔型・年代）は、写真から AI が見た目で選び、SALON BOARD の選択欄に入れます。AI の自信が基準（`settings.json` の `ai.min_required_attribute_confidence`、初期値 0.8）に届かない項目や、写真から分からない項目は「設定しない」にします。この内容は投稿の文章には使いません。

### 10. 動作確認（ai:smoke）

本物の AI（`.env` の段階ごとの設定。書いていない段階は `ai.provider` の AI で、`"anthropic"` 以外なら Gemini）につながるかを、写真1枚で確かめられます（Claude では**数セント程度の費用がかかります**。Gemini の無料枠では費用はかかりませんが、1日の回数を2〜3回使います。投稿はしません）。ツールを止めてから実行してください。

```powershell
npm.cmd run ai:smoke -- C:\写真\確認用.jpg
npm.cmd run ai:smoke -- C:\写真\確認用.jpg --type style --audience mens
```

- 写真を一時フォルダにコピーして、解析・文章の作成・検査を1回ずつ行い、下書きと使った量（回数・トークン数・見積額）を表示します。job は作らず、投稿データも変えません（使った量は予算の記録に入ります）。
- API キーが無いとき・`.env` の AI の行に誤りがあるときは、何も送らずに止まります。接続だけを確かめるなら、写真を使わない `npm.cmd run ai:test`（上の6）が手軽です。スタイルを試すには `verified_menus` の登録が必要です。種類を省くとブログ・レディースで試します。

## 写真ごとの補足ファイル（.json）

写真と同じ名前の `.json` ファイルを、写真と同じ pending のフォルダに置くと、その写真の補足として使います（例：`IMG_0001.jpg` には `IMG_0001.json`）。写真と一緒に取り込まれ、投稿ごとのフォルダに `sidecar.json` として入ります（dry-run ではコピー、本番では移動）。

```json
{
  "category_hint": "perm",
  "verified_menu_ids": ["カット＋パーマ"],
  "target_audience": "20代",
  "notes": "顔周りを軽くしたいというご希望でした"
}
```

| 項目 | 書くこと |
|---|---|
| `category_hint` | この写真のカテゴリー。`config\categories.json` の `id`（例：`perm`）か表示名（例：`パーマ`）。パーマ・ブリーチ・髪質改善など、写真だけでは確かめられない施術のカテゴリーは、ここで指定したときだけ使います |
| `verified_menu_ids` | この写真で行ったメニュー。`salon.json` の `verified_menus` と同じ表記で書きます（スタイル投稿のメニュー欄にそのまま使います） |
| `target_audience` | どんな方向けかのメモ（例：「20代」「お仕事帰りの方」）。メンズ・レディースは置いたフォルダで決まるので、ここには書けません |
| `notes` | 写真についてのメモ（500文字まで）。AI には参考情報として渡します |

- どの項目も省略できます。文字コードは UTF-8 で保存してください（メモ帳の「UTF-8」で保存すれば大丈夫です）。
- 写真より後に `.json` を保存しても、書き込みが終わるまで写真の取込を待ちます。大きすぎる（16KB を超える）ファイルや、同じ名前で拡張子だけ違う写真が2枚あるときの `.json` は使いません（ログに理由を残し、pending に残します）。
- 写真を取り込めなかったとき（読めない画像・同じ画像がすでにある）は、`.json` は pending に残ります。不要なら削除してください。
- 取り込んだ後に直したいときは、その投稿のフォルダ（`images\processing\<job_id>\sidecar.json`、失敗したものは `images\failed\<job_id>\sidecar.json`。dry-run では先頭に `dry-run\` が付きます）を直してください。失敗したものは、直したあと `retry` で再開します。

## 失敗した投稿の再開（retry）

準備や投稿が失敗した写真は `images\failed\<job_id>\`（dry-run では `dry-run\images\failed\<job_id>\`）に移り、理由が `failure.json` に書かれます。原因を直したら（補足ファイルを直す・メニューを登録する など）、次のコマンドで再開できます。ツールが動作中なら動作中のツールに頼み、止まっていればそのまま実行します。

```powershell
npm.cmd run retry -- --id job_id
```

`job_id` は、`images\failed\` の中のフォルダ名（`npm.cmd run status` の失敗した job の一覧にも出ます）に書き換えます。

- 失敗したところから準備し直せるように戻します。画像の解析で失敗したもの・解析が不確かだったものは解析から、文章の作成や検査で失敗したものは文章の作成からやり直します（作り直しの回数は0から数え直します）。SALON BOARD に送信する前に失敗した投稿は「投稿待ち」に戻します（再試行の回数の上限に達していたものは、回数を0に戻して記録に残します）。補足ファイル（`sidecar.json`）はそのまま使います。
- 失敗（FAILED）していない job、読めない画像の job、送信された可能性がある job（結果不明。先に `npm.cmd run reconcile` で照合します）、同じ画像がすでに投稿された job は再開しません。ツールが止まっているときに AI を使えない状態（API キーが無い・予算の上限）なら、再開しても進まないため断ります。
- 引数なしの `npm.cmd run retry` は、送信前の一時的な失敗（画像の添付・通信・画面の読み込みなど）だけをまとめて投稿待ちに戻し、ほかの job は理由ごとの件数を表示します。
- スタイル投稿で `verified_menus` が未登録だった写真は、失敗にせずに待たせているので、メニューを登録すれば `retry` なしで自動的に準備を始めます。`retry` が必要なのは、すでに失敗になったもの（例：準備の途中でメニューの登録を消した、補足ファイルのメニューが登録と一致しない）だけです。

## 投稿履歴の作り直し（history:rebuild）

投稿済みの文章は、重複と言い回しの検査のために `data\history.json`（dry-run は `dry-run\data\history.json`）に残します。このファイルは投稿済みの job から作り直せる控えです。起動のたびに足りない記録を自動で補いますが、ファイルを消してしまったときなどは、ツールを止めてから次のコマンドで作り直せます。

```powershell
npm.cmd run history:rebuild
```

## テンプレート（Excel）の取込

文章の参考にする Excel（`2026ヘアスタイルタイトルテンプレート.xlsx`）の場所とシートの対応は `config\template_mapping.json` に書きます（`file_path` は絶対パスで書けます。`\` は `\\` と2つ重ねます）。動作中のツールは、Excel が変わると自動で読み直します。取込の結果をくわしく確かめたいときは、ツールを止めてから次のコマンドを実行します。

```powershell
npm.cmd run templates:import
```

- Excel を**読み取るだけ**で、変更・移動・コピーはしません。数式は計算せず、Excel が保存した値だけを使います（外部リンク・画像・マクロは開きません）。
- 読み取った内容は `data\cache\templates\` に保存し、Excel が変わったときだけ読み直します。
- 「見つからないシート」「対応表に無い列」が出たら、シート名（末尾の空白も含めて完全一致）や列が `template_mapping.json` と合っているか確認してください。
- Excel が見つからない・読めないときは、前回正常に読み込んだ内容（キャッシュ）で文章の作成を続け、`status` の「テンプレート（Excel）」に注意を出します。前回の内容も無いときは、文章の作成を保留します（`status` に「【生成を保留中】」）。
- 終了コード：0 = 読み取れた、1 = 設定の誤り、または Excel を読み取れない（前回の内容が保存されていれば、文章の生成はそれで続けられます）、2 = ツールの動作中（止めてから実行してください）。

## 公開トレンド（Google トレンドのCSV）の取込

Google トレンドの画面から**手動で書き出した CSV** を `references\trends` に置き、`config\trends.json` の `sources` に1件書き足すと、文章づくりの参考語として取り込めます。書き出し方と設定の書き方は `references\trends\README.md` にあります。動作中のツールは、CSV か設定が変わったときに自動で取り込み直します（取り込めない CSV の注意は、取込元ごとに1日1回ログに出します）。取込結果をくわしく確かめたいときは、ツールを止めてから次のコマンドを実行します。

```powershell
npm.cmd run trends:refresh
```

- CSV を**読み取るだけ**で、変更・移動はしません。ツールが Google トレンドへ自動で接続することはありません（基本版）。
- 取り込んだ内容は `data\cache\trends\` に保存し、CSV が変わったときだけ読み直します。`exported_at` から72時間（`cache_ttl_hours`）を過ぎた内容は「最新」として使いません。
- CSV を置かなくても文章は作れますが、その状態は「公開トレンド未取込」と表示されます。
- 次を変えると、古い取込結果は使われなくなります。動作中のツールは自動で取り込み直します。止めているときは、次に起動したときに取り込み直します（`npm.cmd run trends:refresh` でも取り込めます）：`trends.json` の取込元の設定（`id`・`source_url`・`region`・`period`・`data_kind`・`exported_at`）・`cache_ttl_hours`・`trend_words`/`trend_colors`/`trend_styles`、`keywords.json` の `priority_keywords`/`secondary_keywords`、`categories.json`（カテゴリーの `id`・`label`・`allowed_keywords`）、そして CSV 本体。
- CSV が無くなっただけなら前回の取込結果は期限まで使われますが、読めないものに置き換わったときは使わず、Google トレンドから書き出し直すか元の CSV に戻すよう案内します。
- 終了コード：0 = 取り込めた（または取込元なし）、1 = 設定の誤り、または読めない CSV がある、2 = ツールの動作中（止めてから実行してください）。
- **ご注意：** 対応する2種類の CSV の形（時系列・関連クエリ）は、Google トレンドの書き出しの説明をもとに作ったもので、実際のファイルでの確認はまだできていません。取り込めなかったときや値が合わないときは、開発担当へお知らせください（ファイルの先頭の数行を添えてください）。

### Web検索のトレンド語（毎週日曜・自動）

- 動作中のツールは**毎週日曜の朝6時以降**に1回、文章生成の AI のWeb検索（Gemini は Google 検索、OpenAI は `ai.openai.web_search_model`（初期値 `gpt-6-astra`）の web_search）で「上昇キーワード・よく使われる語」を**メンズヘアとレディースヘアで別々に**調べ、`data\cache\trends\web-trends.json`（メンズ）と `web-trends-ladies.json`（レディース）に記録します。調べた語は、その日曜から14日間、公開トレンドの語と同じように文章づくりの参考にします。メンズの投稿にはメンズの語だけを使い、レディースの語はレディースの投稿を設定したときだけ使います。操作は要りません。
- NG語・確認が必要な施術名・除外語・料金や人気などの誇大な語・記号を含む語は、記録する前に自動で外します。AI を投稿先URLのある方ごとに週1回（メンズ・レディースの両方なら週2回）〜数回使います（失敗したときは2時間以上あけて、その日曜のうちに試し直します。投稿は待ちません）。
- 結果は `npm.cmd run status` の「Web検索のトレンド語（メンズ）」「Web検索のトレンド語（レディース）」の行で確かめられます。今すぐ調べるときは、ツールを止めてから `npm.cmd run trends:web` を実行します。調べるのは、投稿先URL（スタイルかブログ）が設定されている方だけです（どちらも未設定のときは両方。設定の無い方は status に「投稿先URLが設定されていないため調べません」と出ます）。止めたいときは `config\trends.json` の `"web_search": { "enabled": false }` にします。
- 調べた結果は毎週 `トレンド語\トレンド語一覧.xlsx` のシート「メンズ」「レディース」に書き出すので（調べた元の URL はシート「調べた元」）、Excel で開いて見られます（過去の週も残ります）。このファイルはツールが毎回書き直すため、見るだけにしてください（開いたままでも投稿は止まりません。閉じると次の取得のときに書き直します）。
- 使ってほしい語は `トレンド語\手動のトレンド語.xlsx` のシート「メンズ」または「レディース」の A列（左端）に手で書き足せます（1行1語。保存して閉じると、1分ほどでその対象の投稿の参考語に加わります。除外語・NG語は使いません）。このファイルはツールの起動時に無ければ作られ、そのあとツールは読むだけです（前の形の、シートが1枚で語が1つも無いファイルだけは、起動時にこの形へ置き換えます。前の形のファイルに書いた語はメンズの語として使います）。
- 文章生成の AI が Gemini か OpenAI のときだけ使えます（Claude・OpenAI 互換では「Web検索は今は Gemini と OpenAI のときだけ使えます」と記録し、文章づくりはそのまま続けます）。`npm.cmd run trends:web` は日曜でなくても、すぐに調べます。

## 文章の生成に使う設定

- **スタイル投稿の「メニュー」は、`config\salon.json` の `verified_menus` に登録した確認済みのメニューだけから作ります**（AI がメニュー名を作ることはありません）。1件も登録していない間は、スタイルの写真は解析もせずに待たせ（AI の費用もかかりません）、`status` に「スタイル投稿: 【保留中】」と表示します。登録して保存すると、再起動しなくても自動で準備を始めます。お店で実際に提供しているメニュー名を、そのままの表記で書いてください（例：`"verified_menus": ["カット", "カット＋カラー"]`）。ブログ投稿には影響しません。
  - 写真ごとの補足ファイル（`sidecar.json`）の `verified_menu_ids` に、`verified_menus` と同じ表記のメニューを書くと、その写真ではそのメニューだけを使います（全角・半角の違いは同じものとして扱います）。1つも一致しないとき、またはつなげたメニュー名がメニュー欄の上限を超えるときは、その写真のスタイル投稿は止まります。
  - 髪質改善・ブリーチ・縮毛矯正・パーマなど、写真だけでは確かめられない施術の名前を含むメニューは、AI が選ぶメニューの候補に入れません（`keywords.json` の `restricted_terms` で `verified_menu` にした語（酸熱トリートメント・TOKIOトリートメント・ノンジアミンなど）を含むメニューも同じです）。その写真の `sidecar.json` の `category_hint` で指定したカテゴリーの語（`label`・`allowed_keywords`・`verified_terms`）が、メニューに書かれた施術名をすべて含むときだけ、候補に入ります（例：`"category_hint": "perm"` の写真なら「カット＋パーマ」も選べます）。
    - `category_hint` は1つしか書けないため、別々のカテゴリーの施術を含むメニュー（例：「カット＋パーマ・ブリーチなしカラー」）は候補に入りません。
    - 同梱の `categories.json` には、縮毛矯正・ストレートパーマ・ストパー・デジパのカテゴリーがありません。そのため、これらを含むメニューは `category_hint` を書いても候補に入りません。その写真では `verified_menu_ids` でメニューを指定するか、次の項目のとおりカテゴリーを追加してください。
    - 候補が1つも残らないときは、その写真のスタイル投稿は「設定が未完了（CONFIG_INCOMPLETE）」で止まります。案内には、`category_hint` の書き方か、`category_hint` では選べるようにならない理由が表示されます。
    - メニュー名の「パーマなし」「ブリーチ不要」などの打ち消しは読み取りません。そのため、施術を打ち消すだけのメニュー名（例：「メンズカット（パーマ・カラーなし）」）は、その施術を `category_hint` で指定した写真でも候補に入ることがあります。こうしたメニューは `verified_menus` に登録せず、写真ごとに `verified_menu_ids` で指定するのがおすすめです。
  - 縮毛矯正など、同梱のカテゴリーに無い施術について書きたいときは、`categories.json` の `style_categories` にカテゴリーを1件追加します。`requires_verified_menu` を `true` にし、`verified_terms` にその施術の語（例：`["縮毛矯正"]`）を書きます（`id`・`label`・`audiences`・`allowed_keywords`・`template_categories` は、ほかのカテゴリーと同じ書き方です）。その写真の `sidecar.json` に `"category_hint": "<追加した id>"` を書けば、その語をタイトル・コメント・ハッシュタグに書けるようになり、その語を含むメニューも候補に入ります。
  - `verified_menu_ids` で指定したメニューは、施術の名前を含んでいてもメニュー欄にそのまま入ります。ただし、メニュー名は施術の確認にはなりません（次の項目）。
  - **パーマ・ブリーチ・髪質改善などの施術について、タイトル・コメント・ハッシュタグに書いてほしい写真は、その写真の補足ファイル（`sidecar.json`）に `category_hint` を書いてください**（例：`{"category_hint": "perm", "verified_menu_ids": ["カット＋パーマ"]}`。メンズの写真のパーマなら `"mens_perm"` です）。メニュー名だけでは足りません。`verified_menu_ids` で「カット＋パーマ」を指定しても、`verified_menus` に「カット＋パーマ」を登録していても、`category_hint` が無ければ「パーマ」とは書きません。メニュー名の中の言葉（「パーマなし」「ブリーチ不要」などの書き方も含みます）を読み取って判断することはしません。画像解析で見えた色も施術の確認にはなりません（「ブリーチ」などブリーチカラーの施術の語は、`"category_hint": "bleach_color"` が無ければ書きません）。ただし「ハイトーン」は髪色の見た目を表す語なので、画像解析で髪色が「ハイトーン」と判定され、その確からしさが `settings.json` の `ai.min_required_attribute_confidence` 以上の写真では、`category_hint` が無くても使えます。
  - メニューの登録を待っていたスタイル投稿は、登録すると自動で再開します。`category_hint` を書き足した写真など、すでに失敗（CONFIG_INCOMPLETE・IMAGE_ANALYSIS_UNCERTAIN）になったものは、案内に表示される `npm.cmd run retry -- --id job_id` で再開してください（「失敗した投稿の再開（retry）」）。書き足した `category_hint` は、画像解析をやり直さないときも、そのカテゴリーとして使われます。
- **写真だけでは確かめられない施術のカテゴリー**（髪質改善カラー・ブリーチなしカラー・メンズパーマなど）は、その写真の `sidecar.json` の `category_hint` で指定したときだけ使います（メニュー名や画像解析では確認しません）。指定があれば、カテゴリー名とその語（`categories.json` の `label`・`allowed_keywords`）に加えて、`verified_terms` に書いた施術の語（例：髪質改善カラーなら「髪質改善」、メンズパーマなら「パーマ」）もタイトル・本文・ハッシュタグに使えます。それ以外の施術（例：メンズパーマでの「デジタルパーマ」、ブリーチなしカラーでの「ブリーチ」だけ）は書きません。文章を作る前に `sidecar.json` から指定を消した場合も、そのカテゴリーは使いません。
  - `verified_terms` は、確認が必要なカテゴリー（`requires_verified_menu` が `true`）にだけ書けます。ここに書いた語は、そのカテゴリーが確認された写真で使えるようになるだけで、ほかの写真で使えなくなることはありません（例：ツイストスパイラルの「スパイラル」を書いても、ヘアセットの写真の「スパイラル巻き」や、確認されたパーマの写真の「スパイラルパーマ」は使えます）。確認されていない写真で書かない施術の語は、組み込みの語（髪質改善・ブリーチ・縮毛矯正・デジタルパーマなど）、`keywords.json` の `restricted_terms` で `verified_menu` にした語（酸熱トリートメント・ノンジアミンなど）と、確認が必要なカテゴリーの `label`・`allowed_keywords` です（確認の要らないカテゴリーでも使う語、例：透明感カラーは除きます）。
  - カテゴリーの通称（例：ブリーチなしカラーの「ノーブリーチ」「ノンブリーチ」「ブリーチ無し」「ブリーチ不要」「ブリーチレス」、ツイストスパイラルの「ツイストスパイラルパーマ」）は `allowed_keywords` に書きます。そのカテゴリーが確認された写真では使え、確認されていない写真では書きません。ただし「ブリーチレスキュー」の中の「ブリーチレス」は通称として扱いません。ブリーチなしカラーが確認された写真でも、「ブリーチレスキュー」は「ブリーチ」を書いたものとして扱い、それを含むメニューも選びません。
- **ハッシュタグ**は、カテゴリー・写真の特徴・季節・検索ワード・トレンド語など、その投稿に関係する語だけを使います。料金・割引・場所・予約・人気・口コミなど店舗の事実を示すタグ、顔型（丸顔・面長など）だけのタグ、記号や絵文字を含むタグは付けません。検索ワード・トレンド語（取り込んだ CSV・`trends.json`・Excel）のうち、人気・話題・最新・バズ（髪型名のバズカットは除く）・クーポン・予約など店舗の事実を示す語も、文章やタグの材料にしません（`salon.json` の `location_keywords`・`strengths` に書いた語は使えます）。
- **ヘアコンサルティング**は、`salon.json` の `service_claims.hair_consulting` が `false` なら文章にもタグにも書きません。`writing_rules.json` の `include_hair_consulting` が `false` のときは、文章に入れず、タグの候補からも外します。
- **文字数の上限**は、SALON BOARD の画面で確認できるまで `config\writing_rules.json` の `default_limits` の値を使います（スタイル：タイトル30・コメント120・メニュー50、ブログ：タイトル25・本文1000・本文の改行80回まで。見た目の1文字を1と数えます）。画面設定（profile）を確認済みにした投稿先では、画面の上限と比べて厳しいほうを使います。コメントとブログ本文の上限には、末尾に付けるハッシュタグ（`#` と空白を含む）も含みます。
- 「骨格診断」という言葉は、`salon.json` の `service_claims.formal_skeletal_diagnosis` が `true` のときだけ使います。予約の案内（予約・ネット予約など）は、確認済みの予約導線を設定する仕組みができるまで書きません。
- **文章の設定（`writing_rules.json` の書き方・構成・締めの一文や、作業指示書の文章方針）を変えたとき**、すでにできている投稿待ちの文章は前の書き方のままです。`npm.cmd run redraft` を実行すると、まだ投稿に回していない投稿待ちの文章を新しい設定で書き直します（画像の解析はやり直しません。先に `-- --dry` で対象の件数を確かめられます）。投稿に回した・投稿済み・失敗・結果不明の job と、live:single で指定した job は書き直しません。書き直している間、その日の投稿枠はほかの投稿待ちを使うか、書き直しが終わるのを待ちます。

### 文章の検査（投稿前のチェック）

AI が作った文章は、投稿の準備に入る前に必ず検査します。1つでも引っかかると、理由を AI に伝えて作り直します（作り直しの回数は `settings.json` の `ai.max_regenerations`）。主な検査は次のとおりです。

- 空の文章・見えない文字・HTML・許可していない URL（`writing_rules.json` の `allowed_urls` 以外）・電話番号・メールアドレスがないこと。
- ハッシュタグを付けたあとの文字数が上限内で、タグが `hashtags.json` の `min_count`〜`max_count` 個であること。最低個数のタグを付けると文章がほとんど書けない上限のときは、切り詰めずに「設定の調整が必要」として止めます。
- カテゴリー・メニュー（`verified_menus` の組み合わせだけ、料金やクーポンの表記なし）。その写真で使えるメニューがすべて料金などを含むとき（`sidecar.json` で指定したメニューに料金が入っているときを含む）は、作り直しても直らないため、作り直さずに止まります。`salon.json` の `verified_menus` に料金を含まないメニュー名を登録してください。
- 写真と文章が合っていること：色の名前は画像解析で見えた色の系統と同じもの、長さの言葉は解析した長さに合うものだけ。解析で「分からない」とされたこと（ブリーチの有無・薬剤など）は書きません。
- NG語・断定や保証の言葉（絶対・必ず・100%・小顔になる など）・確認できない施術・設定に無い店舗の情報（料金・割引・限定・人気・ランキング・実績・予約・営業時間（「10:00〜20:00」「20:00まで受付」「最終受付19:00」のような時刻を含みます。「朝5:30でも」のように時刻だけを書いた部分は、最後の AI の確認で判断します）・場所・スタッフ）・写真の人物の年齢や顔型の断定がないこと。
  - 施術の語（髪質改善・ブリーチ・酸熱トリートメントなど）を裏付けるのは、その写真の `sidecar.json` で指定したメニューと、確認されたカテゴリーだけです。AI が `verified_menus` から選んだメニューは、その写真の施術の裏付けになりません。メニューの名前の中の語の扱いは、上の「文章の生成に使う設定」と同じ決まりです（例：「ブリーチなしカラー」のメニューでは「ブリーチ」だけは書けません）。
- ヘアコンサルティング（またはカウンセリング・似合わせ提案など）の案内があること、予定日の季節と違う季節の言葉がないこと、関係のないタグ・重複したタグがないこと、押し売りや煽りの言葉がないこと。
- 直近5件の同じ種別の投稿（送信待ちを含む）と同じ書き出し・同じ相談の案内の文、助詞や同義語を入れ替えただけの文、直近3件と同じ「タイトルの型＋切り口」を使っていないこと。
- 過去の投稿と同じタイトル・文章（記号や全角半角の違いは無視）、直近100件・送信待ちの下書きとよく似たタイトル（似ている度合い0.85以上）や文章（0.90以上。`settings.json` の `duplicates` で変更可）、Excel の参考例のタイトルの丸写しや、参考例のコメントと20文字以上同じ部分がないこと。
- 上の検査にすべて通った文章だけ、最後に AI が写真と文章の内容を照らし合わせます（`ai.consistency_check`。`"off"` にすると行いません）。写真と矛盾すると判定された部分や、設定に無い店舗の情報・画像解析で「分からない」とされたことを書いた部分、その写真の `sidecar.json` のメニューや確認されたカテゴリーで裏付けられない施術を書いた部分は作り直します（`verified_menus` は店が提供しているメニューとして伝え、その写真の施術の裏付けにはしません。`salon.json` の `poster_name` は確認済みの情報として伝えます）。ただし、投稿のメニュー欄にある一般的な項目（「カット＋カラー＋トリートメント」の「カラー」「トリートメント」など）を文章で繰り返すだけなら、作り直しません。ブリーチ・髪質改善・縮毛矯正・パーマや、酸熱トリートメントのような名前の付いた施術は、この扱いになりません。この確認が通信エラーなどでできなかったときは、文章を通さずに次の周期でやり直します。

検査に使う言葉の一覧は `config\keywords.json` で変えられます（キーを消すと組み込みの一覧を使います。空にするとその検査を使いません）。

| キー | 中身 |
|---|---|
| `color_terms` | 色の系統（`ブラウン系`・`グレージュ系`・`ハイトーン` など）ごとの色の名前。写真の色の系統に無い名前は使えません |
| `style_terms` | 長さ（`short`・`bob`・`medium` など）ごとの、長さを示すスタイル名 |
| `restricted_terms` | 条件付きの言葉。`allowed_only_if` が `formal_skeletal_diagnosis`（正式な骨格診断があるときだけ）・`verified_menu`（その写真の `sidecar.json` のメニューか、確認されたカテゴリーで裏付けられたときだけ。文章を作るときにも確認できない施術として扱い、その語を含むメニューは AI に選ばせません）・`never`（使わない。文章を作るときにも使わない語として伝えます） |
| `ng_word_exceptions` | NG語の例外。`context_pattern` に書いた言い回しの中の NG語は問題にしません（例：「必ずしも」の中の「必ず」） |

投稿済みの文章は、重複と言い回しの検査のために `data\history.json`（dry-run は `dry-run\data\history.json`）に直近100件まで残します。それより古い投稿と、投稿から `settings.json` の `retention.posted_data_days`（初期値30日）を過ぎた投稿（`retention.enabled` が `true` のとき）は、文章を消して比較用の値だけを残します（同じ文章の再投稿は引き続き防ぎます。比較用の値は重複防止の記録 `dedupe.json` にも残ります）。パソコンを止めている間に期限を過ぎた文章は、次の起動のあとに消します。このファイルが壊れていた場合は、消さずに `history.json.corrupt-日時` という名前で残し、空の状態から続けます。残したファイルには投稿の文章が入っているので、中身を確かめたら削除してください（保持期間を過ぎたものの自動の削除は、今後の版の整理処理で行う予定です）。

## フォルダの説明

共通のフォルダを使うとき（`settings.json` の `shared_root`。[メンズとレディースを1つのフォルダで動かす](#メンズとレディースを1つのフォルダで動かす)）は、`images\pending`・`.env`・`instructions`（共通のフォルダでは `設定`）・`トレンド語` は共通のフォルダにあり、そのほかはこの表のとおりこのフォルダにあります。

| フォルダ | 中身・注意 |
|---|---|
| `起動.bat` | ダブルクリックでツールを起動します（[起動.bat で毎日使う（運用）](#起動bat-で毎日使う運用)） |
| `images\pending\style\mens` | スタイル投稿・男性の写真を置く場所 |
| `images\pending\style\ladies` | スタイル投稿・女性の写真を置く場所 |
| `images\pending\blog\mens` | ブログ投稿・男性向けの写真を置く場所 |
| `images\pending\blog\ladies` | ブログ投稿・女性向けの写真を置く場所 |
| `dry-run\` | dry-run（テスト運転）のデータ一式。本番のデータとは完全に分かれています |
| `data\`、`images\processing`・`failed`・`posted` | 本番（live）用のデータと画像の置き場所 |
| `data\ai-usage\` | AI の利用回数・トークン数・見積額（月ごとの `YYYY-MM.json`）と、Gemini の無料枠の回数の記録（`request-quota.json`）。本物の AI を使ったときだけ作られ、dry-run と本番で共通です（予算と上限の判定に使うので消さないでください） |
| `data\cache\templates\`・`data\cache\trends\` | Excel と トレンドの CSV を読み取った結果の控え（元のファイルは変更しません） |
| `data\history.json`（dry-run は `dry-run\data\history.json`） | 投稿済みの文章の控え（重複の検査用。`history:rebuild` で作り直せます） |
| `logs\` | 記録（ログ）。1日1ファイル（`app-日付.jsonl`） |
| `config\` | 設定ファイル |
| `.env` | AI の API キーと、拡張機能との接続のための秘密の値（`LOCAL_API_TOKEN`。最初の起動で自動で書き込まれます）。人に渡さないでください |
| `data\survey\` | 「画面を調査」で保存した画面の調査結果（入力欄の値・お客様の情報・クッキーは含みません）と、承認の印（`.approved`）。このパソコンの中だけで使い、人に渡したり共有したりしないでください |
| `data\evidence\`（dry-run は `dry-run\data\evidence\`） | 投稿ごとの「登録できたか」の確認の記録（画面の完了表示・一覧で見つけたタイトルの短い抜き書きなど） |
| `data\launcher.lock` | `起動.bat` が動いている間だけある印（2つ目の `起動.bat` を起動しないため。止めると消えます） |
| `docs\task-scheduler-sample.xml`・`docs\acceptance-checklist.md` | タスク スケジューラの登録例と、受け入れチェック表 |
| `data\local-api.json` | 動作中のツールと拡張機能・コマンドがつながるための情報（ツールを止めると消えます。人に渡さないでください） |
| `data\live-single-preview.json` | `live:single` で表示した内容の控え（`--yes` を付けて実行すると消えます） |
| `ledger\`（dry-run は `dry-run\ledger\`） | 本番の送信の記録（送信の直前に1行ずつ書きます）。バックアップから戻したデータに無い送信を見つけるために使うので、**消したり、バックアップから戻したりしないでください** |
| `images\processing\<job_id>\upload.jpg`（または `upload.png`） | SALON BOARD に添付するために、画面の条件（形式・大きさ）に合わせて作った画像。元の画像は変更しません |
| `apps\extension\dist\` | Chrome 拡張機能（`npm.cmd run build:extension` で作ります） |

- 画像を置いてよいのは**上の4つのフォルダだけ**です。`images\pending` の直下や別のフォルダに置いた画像は取り込まず、置き直すよう案内します。男女の区別は置いたフォルダで決まります（AI で推測しません）。
- 対応する画像は JPEG・PNG・WebP です。iPhone の HEIC などは「読めない画像」として失敗になり、`failed` フォルダの `failure.json` に対処法が書かれます。JPEG か PNG で保存し直して、もう一度入れてください。
- コピー中・同期中（OneDrive など）の画像は、書き込みが終わるまで待ってから取り込みます。
- **dry-run では、pending の画像は移動せずコピーします。** 元の画像は pending に残るので、あとで本番に切り替えても使えます。同じ画像は二度取り込みません。
  - そのため dry-run では、起動するたび（`--once` で実行するたび）に、pending に残っている取込済みの画像が「取込済み（dry-run では元の画像を pending に残します）」とログに記録されます。これは注意や警告ではなく、対応は不要です。
  - 同じ画像を別の名前で入れ直した場合は、これまでどおり「同じ画像がすでに登録されている」と警告します。
- 本番（live）では、取り込んだ画像は pending から移動します。
- **`data\` と `dry-run\data\` の中のファイルは手で編集しないでください。** 壊れたファイルを見つけると、ツールはデータを守るために起動を止めます（STATE_CORRUPT）。
- 原画像を長く保管したい場合は、pending に入れる**前に**、別の場所へコピーして保存しておいてください。投稿が済んだ画像は、30日後に自動で整理されます（[30日整理](#30日整理)）。

## 終了コード

コマンドが終わったときの番号（`$LASTEXITCODE` で確認できます）の意味です。

| 番号 | 意味 | どうすればよいか |
|---|---|---|
| 0 | 正常に終わりました | — |
| 1 | 設定ファイルや入力（コマンドの書き方）に誤りがあります | 表示された「ファイル名 項目: 内容」の箇所を直してください |
| 2 | 起動の前提が足りません（ほかに起動中・保存データの破損・フォルダに書き込めない・3001番のポートが使えない など）。`status` では、保存データが壊れている・読み取れないため状態を表示できません。保守用のコマンド（`templates:import`・`trends:refresh`・`history:rebuild`・`ai:smoke`・`ai:test`）では、ツールが動作中です。ツールの動作中に使うコマンド（`pair`・`probe`・`preflight`・`live:single`）では、ツールが起動していない・応答を確認できない（`preflight` では結果が来ない）とき（`retry`・`pause`・`resume`・`reconcile` では、ツールの応答を確認できなかったとき） | `LOCK_CONFLICT` は表示の案内どおり、すでに動いているツールが無いか確認してください（保守用のコマンドは、ツールを Ctrl+C で止めてから実行します）。`PORT_IN_USE` は、ほかのソフト（またはもう1つのツール）が 3001 番（`server.port` の番号。[メンズとレディースを1つのフォルダで動かす](#メンズとレディースを1つのフォルダで動かす)ときのレディース用は 3002 など）を使っていないか確認してください。`STATE_CORRUPT` はファイルを消したり直したりせず、表示されたファイル名を控えて相談してください（下の「以前の版から更新した場合」に当てはまるときを除く） |
| 3 | 想定外のエラーです | `logs` フォルダのログを添えて相談してください |

`起動.bat` の終了コードは「[日常運用](#日常運用)」を見てください。

ロックを取得した後に起きた起動の失敗は、画面に加えて `logs` フォルダのログにも記録されます（設定ファイルの誤りやフォルダを作れないときは画面にだけ表示されます）。

## 以前の版から更新した場合

- 開発のごく初期の版（画像の幅・高さを記録していなかった版）で作った dry-run のデータは、この版では壊れたデータ（`STATE_CORRUPT`）として扱われ、起動も `status` もできません。ツールを止めた状態で `dry-run` フォルダを削除してください。次の実行で dry-run のデータが新しく作られます（pending の元の画像と本番用のデータには影響しません）。
- Plan 1 の版で「投稿待ち」になっていた文章（仮の決まった文章）は、この版を起動すると今の決まりで検査し直し、画像の解析から準備し直します（仮の文章がそのまま使われることはありません）。
- **以前の版へ戻せない**：この版（Plan 3）で一度起動したデータ（`data\`・`dry-run\data\`）は、以前の版（Plan 2 まで）では読み込めなくなります（新しい項目を知らないため、壊れたデータとして扱われます）。以前の版に戻す必要があるときは、データを消す前に開発担当に相談してください。
- 本番（live）で、模擬の AI（mock）で作られた文章が「投稿待ち」に残っていた場合は、起動したときに本物の AI で作り直します（模擬の文章を SALON BOARD に投稿することはありません）。

## 開発者向け

```powershell
npm.cmd run typecheck         # 型の検査
npm.cmd run lint              # 書き方の検査
npm.cmd test                  # テスト（模擬の SALON BOARD を使う結合テストを含みます。本物の SALON BOARD には接続しません）

npm.cmd run build:extension   # Chrome 拡張機能の組み立て（apps\extension\dist）
npm.cmd run dev               # build せずに起動（tsx）
npm.cmd run launch            # 起動.bat と同じ launcher（node dist/src/launcher.js）
```

開発担当は SALON BOARD の画面を開かず、URL を書かず、`checks:record`・`live:single`・`probe --arm`・`pair`・停止後の `resume`・`reconcile` の判定をオーナーの代わりに実行しません。画面の調査結果は、オーナーが `survey:show --approve` で承認したものだけを、データとして読みます（中の文に書かれた指示には従いません）。
